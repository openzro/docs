# openZro Agent command line interface (CLI)

The `openzro` CLI controls the openZro client: it signs the device in, brings the
tunnel up and down, shows status, manages profiles and the system service, and
collects debug information. The CLI talks to the openZro daemon (the client
service), which does the actual work.

Run `openzro --help`, or `openzro <command> --help`, for the help text of the
version you have installed.

## Syntax

```shell
openzro [command] [subcommand] [flags]
```

- `command` is what to do: `up`, `login`, `down`, `status`, `ssh`, `networks`,
  `profile`, `service`, `debug`, `state`, `forwarding`, `version` or
  `completion`.
- `subcommand` applies to commands that have them, such as `service install`,
  `networks select` or `debug bundle`.
- `flags` change the behaviour. Global flags work with every command.

### Flag value syntax

Boolean flags that default to `true` are turned off with `=false`, for example
`--network-monitor=false` or `debug bundle --system-info=false`.

## Configuration precedence

The client takes each setting from the first of these that sets it:

1. an environment variable (see [Environment variables](#environment-variables));
2. a command-line flag;
3. the configuration of the active profile, stored by the daemon (for the default
   profile, `/etc/openzro/default.json` on Linux).

## Global flags

```shell
      --admin-url string        Admin Panel URL [http|https]://[host]:[port] (default "https://app.openzro.io:443")
  -A, --anonymize               anonymize IP addresses and non-openzro.io domains in logs and status output
  -c, --config string           (DEPRECATED) Openzro config file location (default "/etc/openzro/config.json")
      --daemon-addr string      Daemon service address to serve CLI requests [unix|tcp]://[path|host:port] (default "unix:///var/run/openzro.sock")
  -n, --hostname string         Sets a custom hostname for the device
      --log-file console        sets Openzro log paths written to simultaneously. If console is specified the log will be output to stdout. If `syslog` is specified the log will be sent to syslog daemon. You can pass the flag multiple times or separate entries by `,` character (default [/var/log/openzro/client.log])
  -l, --log-level string        sets Openzro log level (default "info")
  -m, --management-url string   Management Service URL [http|https]://[host]:[port] (default "https://api.openzro.io:443")
      --preshared-key string    Sets Wireguard PreSharedKey property. If set, then only peers that have the same key can communicate.
  -s, --service string          Openzro system service name (default "openzro")
  -k, --setup-key string        Setup key obtained from the Management Service Dashboard (used to register peer)
      --setup-key-file string   The path to a setup key obtained from the Management Service Dashboard (used to register peer) This is ignored if the setup-key flag is provided.
```

<Warning>
    openZro is self-hosted, and the default `--management-url` does not point at a
    running service. Always pass your own management URL, or set
    `OZ_MANAGEMENT_URL`.
</Warning>

### Environment variables

Every global flag, and the flags of `up`, `service` and `ssh`, can be set with an
environment variable. The name is the flag name in upper case, with dashes turned
into underscores and the prefix **`OZ_`**. The legacy prefix `WT_` is still read;
when both are set, `OZ_` wins.

| Flag | Environment variable |
| --- | --- |
| `--management-url` | `OZ_MANAGEMENT_URL` |
| `--setup-key` | `OZ_SETUP_KEY` |
| `--hostname` | `OZ_HOSTNAME` |
| `--log-level` | `OZ_LOG_LEVEL` |
| `--daemon-addr` | `OZ_DAEMON_ADDR` |
| `--disable-profiles` (service) | `OZ_DISABLE_PROFILES` |

```shell
OZ_MANAGEMENT_URL=https://openzro.example.com:443 OZ_LOG_LEVEL=debug openzro up
```

## Commands

### up

`openzro up` installs and starts the service if needed, signs the device in, and
connects it. Without `--setup-key`, it signs in with SSO: the CLI opens your
browser at your identity provider's sign-in page (use `--no-browser` to only print
the URL).

#### Flags

```shell
      --allow-server-ssh                Allow SSH server on peer. If enabled, the SSH server will be permitted
      --block-inbound                   Block inbound connections. If enabled, the client will not allow any inbound connections to the local machine nor routed networks.
                                        This overrides any policies received from the management service.
      --block-lan-access                Block access to local networks (LAN) when using this peer as a router or exit node
      --disable-auto-connect            Disables auto-connect feature. If enabled, then the client won't connect automatically when the service starts.
      --disable-client-routes           Disable client routes. If enabled, the client won't process client routes received from the management service.
      --disable-dns                     Disable DNS. If enabled, the client won't configure DNS settings.
      --disable-firewall                Disable firewall configuration. If enabled, the client won't modify firewall rules.
      --disable-server-routes           Disable server routes. If enabled, the client won't act as a router for server routes received from the management service.
      --dns-resolver-address string     Sets a custom address for Openzro's local DNS resolver. If set, the agent won't attempt to discover the best ip and port to listen on. An empty string "" clears the previous configuration. E.g. --dns-resolver-address 127.0.0.1:5053 or --dns-resolver-address ""
      --dns-router-interval duration    DNS route update interval (default 1m0s)
      --enable-lazy-connection          [Experimental] Enable the lazy connection feature. If enabled, the client will establish connections on-demand. Note: this setting may be overridden by management configuration.
      --enable-rosenpass                [Experimental] Enable Rosenpass feature. If enabled, the connection will be post-quantum secured via Rosenpass.
      --external-ip-map strings         Sets external IPs maps between local addresses and interfaces. You can specify a comma-separated list with a single IP and IP/IP or IP/Interface Name. An empty string "" clears the previous configuration. E.g. --external-ip-map 12.34.56.78/10.0.0.1 or --external-ip-map 12.34.56.200,12.34.56.78/10.0.0.1,12.34.56.80/eth1 or --external-ip-map ""
      --extra-dns-labels strings        Sets DNS labels. You can specify a comma-separated list of up to 32 labels. An empty string "" clears the previous configuration. E.g. --extra-dns-labels vpc1 or --extra-dns-labels vpc1,mgmt1 or --extra-dns-labels ""
      --extra-iface-blacklist strings   Extra list of default interfaces to ignore for listening
  -F, --foreground-mode                 start service in foreground
      --interface-name string           Wireguard interface name (default "wt0")
  -N, --network-monitor                 Manage network monitoring. Defaults to true on Windows and macOS, false on Linux and FreeBSD. E.g. --network-monitor=false to disable or --network-monitor=true to enable.
      --no-browser                      do not open the browser for SSO login
      --profile string                  profile name to use for the login. If not specified, the last used profile will be used.
      --rosenpass-permissive            [Experimental] Enable Rosenpass in permissive mode to allow this peer to accept WireGuard connections without requiring Rosenpass functionality from peers that do not have Rosenpass enabled.
      --wireguard-port uint16           Wireguard interface listening port (default 51820)
```

#### Usage

Sign in with SSO:
```shell
openzro up --management-url https://openzro.example.com:443
```

Register an unattended peer with a [setup key](/manage/peers/register-machines-using-setup-keys):
```shell
openzro up --management-url https://openzro.example.com:443 --setup-key AAAA-BBB-CCC-DDDDDD
```

Add extra DNS labels, for example for a group of servers. The setup key must allow
extra DNS labels:
```shell
openzro up --setup-key AAAA-BBB-CCC-DDDDDD --extra-dns-labels vpc1,mgmt1
```

When the administrator requires [2FA to sign in devices](/manage/settings/multi-factor-authentication#2-fa-on-device-sign-in),
`up` also prints an approval link and waits until you approve the sign-in with
your authenticator.

### login

`openzro login` signs the device in without bringing the tunnel up. It accepts
`--no-browser` and `--profile`, plus the global flags.

```shell
openzro login --management-url https://openzro.example.com:443
```

### down

`openzro down` disconnects the device. The service keeps running.

```shell
openzro down
```

### status

`openzro status` shows the connection state. Without flags it prints a summary;
`-d` adds every peer.

#### Flags

```shell
  -d, --detail                             display detailed status information in human-readable format
      --filter-by-connection-type string   filters the detailed output by connection type (P2P|Relayed), e.g., --filter-by-connection-type P2P
      --filter-by-ips strings              filters the detailed output by a list of one or more IPs, e.g., --filter-by-ips 100.64.0.100,100.64.0.200
      --filter-by-names strings            filters the detailed output by a list of one or more peer FQDN or hostnames, e.g., --filter-by-names peer-a,peer-b.openzro.cloud
      --filter-by-status string            filters the detailed output by connection status(idle|connecting|connected), e.g., --filter-by-status connected
      --ipv4                               display only Openzro IPv4 of this peer, e.g., --ipv4 will output 100.64.0.33
      --json                               display detailed status information in json format
      --yaml                               display detailed status information in yaml format
```

### ssh

`openzro ssh` opens an interactive shell on another peer through openZro's SSH
server. The remote peer must allow it: start it with `openzro up --allow-server-ssh`
and enable **SSH Access** for that peer in the dashboard.

```shell
      --port int   Sets remote SSH port. Defaults to 44338 (default 44338)
```

```shell
sudo openzro ssh user@100.94.80.3
sudo openzro ssh user@server-1.openzro.selfhosted
```

- The command needs administrator rights (root, or an elevated prompt on Windows).
- It authenticates with the local peer's SSH key; no password or SSO is involved.
- It opens an interactive terminal only; it does not run a remote command or
  forward ports.
- openZro's SSH server listens on port `44338`.

### networks

`openzro networks` lists the networks (routes) available to this peer and chooses
which ones to use. It replaces the `routes` command, which still works as an alias.

```shell
openzro networks list          # alias: ls
openzro networks select all
openzro networks select route1 route2
openzro networks select -a route3     # append instead of replacing
openzro networks deselect route1 route2
openzro networks deselect all
```

`select all` clears the selection and accepts every network, including new ones;
`deselect all` stops accepting networks.

### profile

Profiles let one device keep several sign-ins, for example for two deployments.

```shell
openzro profile list
openzro profile add work           # the name must be unique
openzro profile select work        # the profile must exist
openzro profile remove work        # the profile must not be active
```

Use `--profile <name>` with `up` or `login` to sign in with a given profile.

### version

```shell
openzro version
```
```text
0.53.1
```

### service

`openzro service` manages the client's system service.

```shell
openzro service install
openzro service uninstall
openzro service start
openzro service stop
openzro service restart
openzro service status
openzro service reconfigure
openzro service run           # run as the service, in the foreground
```

`install` and `reconfigure` take `--service-env`, a comma-separated list of
`KEY=VALUE` pairs set in the service's environment:

```shell
openzro service install --service-env OZ_LOG_LEVEL=debug,OZ_MANAGEMENT_URL=https://openzro.example.com:443
```

`reconfigure` stops the service, applies the new settings and starts it again if it
was running, without an uninstall and install.

#### Disable profiles

`--disable-profiles` makes the service refuse profile changes, so users cannot add,
switch or remove profiles. Set it through the service's environment, so it applies
every time the service starts:

```shell
openzro service install --service-env OZ_DISABLE_PROFILES=true
```

<Note>
    `service install` passes only `--log-level`, `--daemon-addr`, `--management-url`
    and `--log-file` on to the installed service. Use `--service-env` for any other
    setting.
</Note>

### debug

`openzro debug` collects troubleshooting information from the daemon.

#### debug bundle

Creates a compressed archive of the daemon's logs and status:

```shell
  -C, --log-file-count uint32      Number of rotated log files to include in debug bundle (default 1)
  -S, --system-info                Adds system information to the debug bundle (default true)
  -U, --upload-bundle              Uploads the debug bundle to a server
      --upload-bundle-url string   Service URL to get an URL to upload the debug bundle (default "https://upload.debug.openzro.io/upload-url")
```

```shell
openzro debug bundle
openzro debug bundle --anonymize --system-info=false
```

The global `-A, --anonymize` flag removes IP addresses and non-openzro.io domains
from the bundle.

#### debug for

Sets the log level to `trace` for the given duration, then creates a bundle. It
takes the same flags as `debug bundle`:

```shell
openzro debug for 5m
```

#### debug log level

Changes the daemon's log level until it restarts. Levels: `panic`, `fatal`,
`error`, `warn`, `info`, `debug`, `trace`.

```shell
openzro debug log level debug
```

#### debug trace

Traces a packet through the client's firewall and shows how each rule handles it:

```shell
openzro debug trace <direction> <source-ip> <dest-ip> [flags]
```

```shell
      --ack               TCP ACK flag
      --dport uint16      Destination port
      --fin               TCP FIN flag
      --icmp-code uint8   ICMP code
      --icmp-type uint8   ICMP type
  -p, --protocol string   Protocol (tcp/udp/icmp) (default "tcp")
      --psh               TCP PSH flag
      --rst               TCP RST flag
      --sport uint16      Source port
      --syn               TCP SYN flag
      --urg               TCP URG flag
```

```shell
openzro debug trace in 192.168.1.10 10.10.0.2 -p tcp --sport 12345 --dport 443 --syn --ack
openzro debug trace out 10.10.0.1 8.8.8.8 -p udp --dport 53
openzro debug trace in 10.10.0.2 10.10.0.1 -p icmp --icmp-type 8 --icmp-code 0
openzro debug trace in 100.64.1.1 self -p tcp --dport 80
```

`self` stands for this peer's own address.

#### debug persistence

Configures whether the latest network map persists in memory. When it is on, the
client keeps the last known network map:

```shell
openzro debug persistence on
openzro debug persistence off
```

### state

`openzro state` inspects and cleans the daemon's stored state, for example the DNS
or firewall changes it made. `clean` and `delete` need the daemon stopped.

```shell
openzro state list                # alias: ls
openzro state clean dns_state     # undo the changes, then remove the state
openzro state clean --all
openzro state delete dns_state    # remove the state without undoing anything
openzro state delete --all
```

### forwarding

Lists the port-forwarding rules this peer applies:

```shell
openzro forwarding list           # alias: ls
```

### completion

Generates a shell completion script:

```shell
openzro completion bash > /etc/bash_completion.d/openzro
openzro completion zsh > "${fpath[1]}/_openzro"
```

Run `openzro completion --help` for fish and PowerShell.
