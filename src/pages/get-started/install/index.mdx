# Install openZro

The openZro client (agent) connects a device to an openZro deployment. New to
openZro? Start with the [Quickstart Guide](/get-started), which sets up the
dashboard and connects your first client.

openZro is self-hosted: there is no hosted service. If you don't have a
deployment yet, see the [self-hosting quickstart](/selfhosted/selfhosted-quickstart).

The quickest way to install a client is the install page of your own dashboard,
`https://<your-dashboard>/install`, or **Peers → Add peer**. It shows the command
for each platform with your management URL already filled in.

## Point the client at your deployment

Every client needs your management URL. Without it, the client tries a default
address that does not exist and cannot connect.

- **CLI:** pass `--management-url https://<your-management>:443` to `openzro up`,
  or set `OZ_MANAGEMENT_URL`.
- **Desktop app:** open **Settings → Advanced Settings** from the openZro icon in
  the system tray and enter the management URL.

## Running openZro with SSO login

### Desktop app
Launch the openZro desktop app and click **Connect**. Your browser opens your
identity provider's sign-in page; once you sign in, the device connects.

### CLI
```bash
openzro up --management-url https://<your-management>:443
```

The CLI opens your browser at your identity provider's sign-in page:

```text
Please do the SSO login in your browser.
If your browser didn't open automatically, use this URL to log in:

<your identity provider's sign-in URL>
```

With the bundled identity provider, the sign-in page looks like this:

<p>
    <img src="/docs-static/img/get-started/onboarding/01_openzro-sso.jpeg" alt="openZro sign-in page" className="imagewrapper"/>
</p>

When the login completes, the CLI prints `Connected`.

<Note>
    If your administrator requires [2FA to sign in devices](/manage/settings/multi-factor-authentication#2-fa-on-device-sign-in),
    the client also opens an approval page where you enter a code from your authenticator app.
</Note>

Check the connection:
```bash
openzro status
```

## Running openZro with a setup key

To register a server or another unattended peer, use a
[setup key](/manage/peers/register-machines-using-setup-keys). This is useful
when you provision many machines with tools like Ansible or Terraform.

```bash
openzro up --management-url https://<your-management>:443 --setup-key <SETUP KEY>
```

With **Docker**:
```bash
docker run --rm -d \
  --cap-add=NET_ADMIN \
  -e OZ_SETUP_KEY=<SETUP KEY> \
  -e OZ_MANAGEMENT_URL=https://<your-management>:443 \
  -v openzro-client:/var/lib/openzro \
  ghcr.io/openzro/openzro:latest
```

If you leave out `--setup-key`, `openzro up` starts the SSO login in your browser
instead.

Check the connection, then the tunnel interface and its openZro IP:

```bash
openzro status
```

On **Linux**:
```bash
ip addr show wt0
```
On **macOS**:
```bash
ifconfig utun100
```
On **Windows**:
```bash
netsh interface ip show config name="wt0"
```
