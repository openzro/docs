# pfSense Installation

<Warning>
    **Not validated yet.** The openZro client builds and passes its tests on FreeBSD in CI,
    but no FreeBSD package is published yet, so on pfSense this page uses the NetBird community package (agent and UI
    plugin) pointed at your openZro management server. That combination has not been tested against
    openZro. Native pfSense support for openZro is being planned; until then, test
    it in a lab before relying on it.
</Warning>

The NetBird project publishes a pfSense package
([netbirdio/pfsense-netbird](https://github.com/netbirdio/pfsense-netbird/releases))
with the agent and a firewall UI integration. openZro forked NetBird at
`v0.52.2`, and the agent talks to management over the same protocol, so the
package can be pointed at an openZro management server instead of NetBird's.
Newer NetBird agents may use features openZro does not have.

<Note>
    The NetBird client (agent) is BSD-3-Clause licensed, like openZro's client.
    The package is published by the NetBird project, not by openZro or Netgate.
</Note>


## Prerequisites

- Shell/SSH access to pfSense (via Web UI shell or remote SSH)
- A [setup key](/manage/peers/register-machines-using-setup-keys#types-of-setup-keys) to authenticate and register the pfSense device
- The latest two `.pkg` files from
  [netbirdio/pfsense-netbird/releases](https://github.com/netbirdio/pfsense-netbird/releases) —
  one for the agent (`netbird-<version>-<arch>.pkg`) and one for
  the UI plugin (`pfSense-pkg-NetBird-<version>-<arch>.pkg`)

## Installation

1. **SSH into your pfSense system**

   ```sh
   ssh admin@<pfsense-ip>
   ```

   If remote SSH is enabled, or use the built-in shell via the
   pfSense Web UI (`Diagnostics` > `Command Prompt`).

2. **Download the agent**

   ```sh
   fetch https://github.com/netbirdio/pfsense-netbird/releases/latest/download/netbird-<version>-<arch>.pkg
   ```

   Replace `<version>` and `<arch>` with the values from the latest
   release. Most pfSense installations are `x86_64`; appliances on
   ARM use `aarch64`.

3. **Download the pfSense plugin**

   ```sh
   fetch https://github.com/netbirdio/pfsense-netbird/releases/latest/download/pfSense-pkg-NetBird-<version>-<arch>.pkg
   ```

4. **Install both packages**

   ```sh
   pkg add -f netbird-<version>-<arch>.pkg
   pkg add -f pfSense-pkg-NetBird-<version>-<arch>.pkg
   ```

5. **Verify the installation**

   The configuration UI should now appear under `VPN` > `NetBird` in the
   pfSense menu. The label says NetBird because that is the package's name;
   you point it at openZro in the next step.

## Configuration

### Authenticate the machine

In `VPN` > `NetBird`, fill out the authentication form:

- **Management URL**: enter your openZro management server, e.g.
  `https://your-management.example.com:443`. Do **not** leave the
  default, which points at NetBird's hosted service.
- **Setup Key**: paste a setup key issued from your openZro
  dashboard.

Click `Save`.

### Verify connection status

Open `Status` > `NetBird` in the pfSense menu. It shows the connected peers and
the health of the management, signal and relay connections, which should point
at your openZro deployment.

### Assign the WireGuard interface

After authentication, a new interface named `wt0` will be available
but unassigned. Assign it via `Interfaces` > `Assignments`. Under
`Available network ports`, select `wt0(wt0)` and click `Add`.

<p>
    <img src="/docs-static/img/get-started/pfSense/new_interface.png" alt="NewInterface" className="imagewrapper-big"/>
</p>

### Enable the interface

Go to `Interfaces` > `OPT1` (or whatever name pfSense gave the new
assignment), then:

- **Enable**: `✓ Enable Interface`
- **Description**: `openZro`

Click `Save`, then `Apply changes`.

<p><img src="/docs-static/img/get-started/pfSense/enable_interface.png" alt="enableInterface" className="imagewrapper-big"/></p>

### Configure firewall rules

Permit all traffic on the openZro interface in pfSense — openZro's
own access policies (ACLs) handle the access control. Create rules
under `Firewall` > `Rules` on the new interface tab:

1. Click `Add` to create the rule
2. Configure:
   - **Action**: `Pass`
   - **Interface**: `OPENZRO` (the description you set above, in caps)
   - **Address Family**: `IPv4`
   - **Protocol**: `Any`
   - **Source**: `Any`
   - **Destination**: `Any`
   - **Description**: `Allow all on openZro (managed by openZro ACLs)`
3. Click `Save`, then `Apply Changes`

<p><img src="/docs-static/img/get-started/pfSense/firewall_rules.png" alt="firewallRules" className="imagewrapper-big"/></p>

### Static port for relayed connections

By default, pfSense's automatic outbound NAT randomizes source
ports, which can break openZro's NAT traversal (hole punching).
Add a Static Port mapping for the openZro host so direct connections
work reliably:

1. **Switch outbound NAT mode**:
   - `Firewall` > `NAT` > `Outbound`
   - Select `Hybrid Outbound NAT rule generation`, click `Save`

2. **Add a static-port rule**:
   - Click `Add` (Up arrow) to create a new rule at the top
   - **Interface**: `WAN`
   - **Address Family**: `IPv4`
   - **Protocol**: `UDP`
   - **Source**: `Network` — IP of the openZro host
   - **Destination**: `Any`
   - **Translation / Static Port**: ✓ check
   - **Description**: `openZro Static Port`
   - Click `Save` and `Apply Changes`

3. **Reset existing states** so the new rule takes effect for
   in-flight connections:
   - `Diagnostics` > `States`
   - Filter by the openZro host IP, click `Kill`

4. **Restart the agent** (the package's binary is `netbird`):
   - `netbird service restart` on the device
   - `netbird status -d` to verify

## Uninstallation

```sh
pkg delete netbird pfSense-pkg-NetBird
```
