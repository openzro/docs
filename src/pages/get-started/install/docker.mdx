# Docker Installation

The openZro client (agent) connects a device to an openZro deployment. openZro is
self-hosted; if you don't have a deployment yet, see the
[self-hosting quickstart](/selfhosted/selfhosted-quickstart).

The client image is published to the GitHub Container Registry as
`ghcr.io/openzro/openzro`, for `amd64` and `arm64`. Use `latest`, or pin a release
tag such as `0.53.1-alpha.103` (no `v` prefix).

## Docker run

Set your [setup key](/manage/peers/register-machines-using-setup-keys) and your
management URL, then run:

```bash
docker run --rm -d \
  --name PEER_NAME --hostname PEER_NAME \
  --cap-add=NET_ADMIN --cap-add=SYS_ADMIN --cap-add=SYS_RESOURCE \
  -e OZ_SETUP_KEY=<SETUP KEY> \
  -e OZ_MANAGEMENT_URL=https://<your-management>:443 \
  -v openzro-client:/var/lib/openzro \
  ghcr.io/openzro/openzro:latest
```

openZro uses eBPF and raw sockets, so `SYS_ADMIN` and `SYS_RESOURCE` are
recommended alongside `NET_ADMIN`. The exact needs vary with the Docker daemon,
operating system and kernel version.

<Note>
    The container reads its settings from `OZ_`-prefixed environment variables,
    for example `OZ_SETUP_KEY`, `OZ_MANAGEMENT_URL` and `OZ_HOSTNAME`. See
    [Environment variables](/get-started/cli#environment-variables) for how they
    map to the client's flags.
</Note>

## Docker Compose

```yaml
services:
  openzro-client:
    container_name: openzro-client
    hostname: <HOSTNAME>
    cap_add:
      - NET_ADMIN
      - SYS_ADMIN
      - SYS_RESOURCE
    devices:
      # Required when using userspace mode or when the kernel module is not available
      - /dev/net/tun
    network_mode: host
    environment:
      - OZ_SETUP_KEY=<SETUP KEY>
      - OZ_MANAGEMENT_URL=https://<your-management>:443
    volumes:
      - openzro-client:/var/lib/openzro
    image: ghcr.io/openzro/openzro:latest
volumes:
  openzro-client:
    name: openzro-client
```

## Check the connection

Run the CLI inside the container:

```bash
docker exec <container> openzro status
docker exec <container> ip addr show wt0
```

## Troubleshooting

1. **The container never connects.** Check that `OZ_MANAGEMENT_URL` is set.
   There is no hosted service: without it, the client tries a default address
   that does not exist.
2. **The management URL is wrong.** Recreate the container with the correct
   `OZ_MANAGEMENT_URL`. The client keeps its configuration in the
   `openzro-client` volume, so remove the volume too if you want a clean start.
