# Manage JWT-Claim Groups

You followed a **Manage in JWT provisioning** link from the openZro dashboard's Groups page. The group shows **Issued
via JWT**: its membership comes from a group claim in the token your identity provider issues, not from SCIM or the
dashboard. To change who is in it, change the claim at the identity provider.

## How JWT group sync works

JWT group sync is configured per account under **Settings → Groups**, in the **JWT group sync** card:

- **Enable JWT group sync** turns it on.
- **JWT claim** is the name of the claim that holds the user's groups, for example `groups`. There is no default; if
  it is empty, nothing is synced.
- **JWT allow group** (optional): only users who have this group in the claim may sign in.

Each time a user calls the openZro API with a token (the dashboard does this on every page) or signs in a device with
SSO, openZro reads the claim and updates the user's groups:

1. A group named in the claim that doesn't exist yet is created with **Issued via JWT**.
2. The user is added to every JWT group named in the claim, and removed from JWT groups that are no longer in it. The
   result is saved on the user.
3. Groups created in the dashboard, through the API or by SCIM are never added or removed by JWT sync.

The claim must be a JSON array of strings, for example `"groups": ["devops", "support"]`. Any other shape, such as a
single string, is read as no groups.

Peers follow their owner's groups only when **Enable user group propagation** is on, in the same tab. Without it,
JWT groups are assigned to users, and to their peers only when the peers are registered.

<Note>
On self-hosted openZro, Dex forwards upstream groups only from connectors configured with `insecureEnableGroups: true`
and the `groups` scope. See [JWT Group Sync](/selfhosted/identity-providers#jwt-group-sync) for how to set this up and
how to configure group claims in common identity providers.
</Note>

## Rename a JWT-claim group

Renaming a JWT group in openZro has no effect: the next request from a user whose claim still carries the old name
re-creates a group with the old name. To rename it:

1. Change the group name in the claim at your identity provider.
2. Have users sign in again so their tokens carry the new name.
3. A new JWT group with the new name appears and users move into it. The old group stays, empty, until you delete it.

## Decommission a JWT-claim group

Remove the group from the claim at your identity provider. Users leave the group the next time they use openZro with a
new token.

JWT groups are not deleted automatically. The dashboard does not allow editing or deleting them; an administrator can
delete an empty JWT group through the API (`DELETE /api/groups/{groupId}`). The deletion is rejected while policies,
routes, or other resources still reference the group.
