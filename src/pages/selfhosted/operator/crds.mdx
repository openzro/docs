# Operator CRD reference

The openZro operator serves these custom resources. The authoritative schemas are the CRDs shipped in the
[`openzro-operator` Helm chart](https://github.com/openzro/helms/tree/main/charts/openzro-operator/crds).

| Kind | API version | Scope | Purpose |
|---|---|---|---|
| `OZGroup` | `openzro.io/v1` | Namespaced | An openZro group |
| `OZPolicy` | `openzro.io/v1` | Cluster | An access policy between openZro groups |
| `OZSetupKey` | `openzro.io/v1` | Namespaced | A setup key, stored in a Secret, used to inject openZro sidecars |
| `OZRoutingPeer` | `openzro.io/v1` | Namespaced | A Deployment of openZro routing peers for the cluster |
| `OZResource` | `openzro.io/v1` | Namespaced | A network resource, usually created from an annotated Service |
| `Group`, `SetupKey`, `NetworkResource`, `NetworkRouter`, `SidecarProfile` | `openzro.io/v1alpha1` | Namespaced | Newer resources used by the Gateway API integration |

Every resource reports its state as conditions of type `Ready` in `status.conditions`.

## OZGroup

Creates an openZro group, or adopts an existing group with the same name.

```yaml
apiVersion: openzro.io/v1
kind: OZGroup
metadata:
  name: backend-team
  namespace: openzro
spec:
  name: "Backend Team"   # immutable
```

`status.groupID` holds the openZro group ID.

## OZPolicy

Creates an openZro access policy. `sourceGroups` and `destinationGroups` are openZro group **names**. The operator
creates one policy per protocol, and adds the network resources of `OZResource` objects that reference the policy
through `policyName` to its destinations.

```yaml
apiVersion: openzro.io/v1
kind: OZPolicy
metadata:
  name: devops-ssh        # cluster-scoped: no namespace
spec:
  name: "DevOps SSH"
  description: "DevOps can SSH into cluster services"
  sourceGroups: ["devops"]
  destinationGroups: ["k8s-services"]
  protocols: ["tcp"]      # tcp, udp
  ports: [22]
  bidirectional: false    # default true
```

Status: `tcpPolicyID`, `udpPolicyID`, `managedServiceList`, `lastUpdatedAt`.

## OZSetupKey

Points at a Secret that holds an existing openZro setup key. The operator checks that the key is valid and marks the
resource `Ready`; pods annotated with `openzro.io/setup-key: <name>` then get an openZro sidecar that uses it. The
operator does not create setup keys for this resource: create the key in the dashboard and store it in the Secret.

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-setup-key
  namespace: default
stringData:
  setupkey: EEEEEEEE-EEEE-EEEE-EEEE-EEEEEEEEEEEE
---
apiVersion: openzro.io/v1
kind: OZSetupKey
metadata:
  name: app-setup-key
  namespace: default
spec:
  secretKeyRef:
    name: app-setup-key
    key: setupkey
  # managementURL: https://openzro.example.com   # optional, defaults to the operator's
  # volumes: / volumeMounts: added to the injected sidecar
```

## OZRoutingPeer

Runs openZro routing peers so the rest of your network can reach the cluster. For each `OZRoutingPeer`, the operator
creates an openZro network named after the cluster, a group, a reusable setup key (stored in a Secret named after the
resource), a network router, and a Deployment of openZro clients (`--openzro-client-image`) that use that key.

```yaml
apiVersion: openzro.io/v1
kind: OZRoutingPeer
metadata:
  name: router
  namespace: openzro
spec:
  replicas: 2
  resources: {}
  labels: {}
  annotations: {}
  nodeSelector: {}
  tolerations: []
  volumes: []
  volumeMounts: []
  # privileged: true
  # ephemeral: false            # register the peers as ephemeral
  # exemptFromAdmission: false  # skip Device Admission for these peers
```

Status: `networkID`, `setupKeyID`, `routerID`.

## OZResource

A network resource in an openZro network. The operator usually creates these itself from Services annotated with
`openzro.io/expose: "true"`; see [Expose Kubernetes Services](/manage/integrations/kubernetes#expose-kubernetes-services-to-open-zro-network).

```yaml
apiVersion: openzro.io/v1
kind: OZResource
metadata:
  name: postgres
  namespace: default
spec:
  name: "postgres.default"
  networkID: "<openZro network ID>"   # immutable; the routing peer's status.networkID
  address: "postgres.default.svc.cluster.local"
  groups: ["k8s-postgres"]             # openZro group names; created if missing
  # policyName: devops-ssh             # attach to an OZPolicy as a destination
  # policySourceGroups: ["devops"]
  # tcpPorts: [5432]
  # udpPorts: []
```

Status: `networkResourceID`, plus the applied policy, groups and ports.

## Deletion

The operator sets finalizers (`openzro.io/cleanup`, `openzro.io/group-cleanup`, `openzro.io/routing-peer-cleanup`,
`openzro.io/resource-cleanup`) so deleting a resource also removes what it created in openZro. Delete the custom
resources before uninstalling the operator, or the finalizers block their deletion.

<Note>
    The operator's own `crds/` directory lags behind the chart; use the chart's CRDs as the reference.
</Note>
