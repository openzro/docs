# Ansible Quickstart (lab, single-node)

Stand up a working openZro server stack on a single Linux VM in
~10 minutes. This is the lab path — small, all-in-one, SQLite,
self-signed cert. For production / HA, see
[Multi-node HA deployment](/selfhosted/ansible/multi-node).

## Prerequisites

- A Linux VM (Debian 12+, Ubuntu 22.04+, RHEL / Rocky / AlmaLinux 9+,
  or Fedora 41+) reachable via SSH from your workstation
- Root or sudo access on the VM
- ansible-core **2.18+** on your workstation (needed for dnf5 on
  Fedora and RHEL 10)
- A DNS record (or `/etc/hosts` entry on test machines) pointing
  at the VM's public IP — this guide uses `openzro.example.com`

## 1. Clone the repo

```bash
git clone https://github.com/openzro/openzro-ansible.git
cd openzro-ansible
ansible-galaxy install -r requirements.yml
```

`requirements.yml` installs the collections the roles use
(certificates, firewalld, SELinux, cloud load balancers).

## 2. Configure the inventory

Edit `inventories/lab/hosts.yml` to point at your VM:

```yaml
all:
  hosts:
    openzro1:
      ansible_host: 203.0.113.5     # your VM's IP
      ansible_user: root            # SSH user

  children:
    management:
      hosts:
        openzro1:
    signal:
      hosts:
        openzro1:
    relay:
      hosts:
        openzro1:
    dashboard:
      hosts:
        openzro1:
```

Keep the `children` section: each component is installed on the hosts
of its group, so the all-in-one host must be in all four.

## 3. Configure group vars

Copy the example and fill in the required values:

```bash
cp inventories/lab/group_vars/all.yml.example \
   inventories/lab/group_vars/all.yml
```

Open `inventories/lab/group_vars/all.yml` and set:

```yaml
openzro_public_domain: "openzro.example.com"

openzro_relay_public_address: "{{ openzro_public_domain }}"
openzro_relay_port: 33080
openzro_relay_auth_secret: "REPLACE_WITH_BASE64_RANDOM_32B"   # openssl rand -base64 32

openzro_oidc_issuer: "https://idp.example.com"
openzro_oidc_client_id: "openzro-dashboard"
openzro_oidc_client_secret: "REPLACE_WITH_IDP_SECRET"
openzro_oidc_supported_scopes: "openid profile email groups"

# SQLite is fine for the lab. Postgres is required for HA.
openzro_datastore_engine: "sqlite"

# certbot_http | certbot_dns | byo | self_signed (lab only)
openzro_tls_mode: self_signed

openzro_cloud: none
```

The file's inline comments describe the other settings: the dashboard
install method, firewalld and SELinux handling, version pinning, and a
custom package mirror (`openzro_repo_baseurl_apt`,
`openzro_repo_baseurl_rpm`) for air-gapped hosts.

<Note>
The Ansible roles install management, signal, relay, the dashboard and
nginx. They do **not** install an identity provider (Dex or other) or
Coturn: point `openzro_oidc_issuer` at an existing OIDC provider (see
[Identity Providers](/selfhosted/identity-providers)). No STUN or TURN
servers are configured, so peers rely on the openZro Relay when a
direct connection fails.
</Note>

## 4. Run the playbook

```bash
ansible-playbook -i inventories/lab playbooks/site.yml
```

What happens, idempotently:

1. On RHEL-family hosts, enables EPEL, opens the needed firewalld
   ports and sets the SELinux boolean nginx needs
2. Imports `pkg.openzro.io`'s signing key and adds the APT or RPM repo
3. Installs the native packages (`openzro-management`,
   `openzro-signal`, `openzro-relay`)
4. Installs the dashboard: the `openzro-dashboard` package on
   Debian/Ubuntu, or the `ghcr.io/openzro/dashboard` container under
   podman elsewhere
5. Renders `/etc/openzro/management.json` and the
   `/etc/default/openzro-{management,signal,relay}` env files
6. Provisions nginx with the certificate from `openzro_tls_mode`
7. Enables and starts every systemd unit

Total time on a 2 vCPU / 4 GB VM: ~3–5 minutes (most of it is
package downloads).

## 5. Verify

```bash
# Daemons up?
ansible -i inventories/lab all -m shell -a "systemctl is-active openzro-management openzro-signal openzro-relay nginx"

# Dashboard reachable?
curl -k https://openzro.example.com/

# Management REST API up? (401 without a token is the expected answer)
curl -k -o /dev/null -w "%{http_code}\n" https://openzro.example.com/api/users
```

Open `https://openzro.example.com/` in a browser — accept the
self-signed cert warning, sign in via your OIDC provider, and
the dashboard loads with empty groups / peers / policies.

## Sizing reference

A single all-in-one VM is plenty for < 100 peers:

| Resource | Size |
|---|---|
| CPU | 2 vCPU |
| RAM | 4 GB |
| Disk | 40 GB SSD |
| Network | 1 Gbps |

Components colocated on that one host:
`management` + `signal` + `relay` + `dashboard` + `nginx` +
`SQLite`.

For larger deployments, see
[Multi-node HA deployment](/selfhosted/ansible/multi-node) — that
guide covers the controller + relay-tier split, cluster coordinator
for HA management, and cloud-LB integration.

## Common issues

- **"Host key verification failed"** — first SSH connect from the
  Ansible runner. Run `ssh-keyscan <ip> >> ~/.ssh/known_hosts` or
  set `host_key_checking = False` in `ansible.cfg`.
- **APT repo signature error** — the role imports the openZro
  signing key automatically; if it fails, your VM has no outbound
  HTTPS to `pkg.openzro.io`. Whitelist that host in egress rules.
- **Dashboard 502 on RHEL/Fedora** — usually SELinux blocking nginx
  from reaching the upstreams; check that `openzro_manage_selinux` was
  left on. With the container install method, the container may also
  still be pulling on first start.
- **OIDC redirect mismatch** — the IdP needs the dashboard's
  callback URL whitelisted. Check the dashboard
  [identity-providers docs](/selfhosted/identity-providers) for
  the exact value to add.
