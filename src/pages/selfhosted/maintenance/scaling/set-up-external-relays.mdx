# Set Up External Relay Servers

The openZro Relay forwards encrypted traffic between peers that cannot connect directly. The stack generated by
`configure.sh` runs one relay next to management. This guide adds relays on other machines, for example in other
regions.

## Requirements

For each relay:

- A Linux machine with Docker and a public DNS name, for example `relay-us.example.com`.
- The relay port open on **both TCP and UDP**: TCP for WebSocket, UDP for QUIC. This guide uses 443.
- TCP port 80 open if you use Let's Encrypt.
- The relay secret from the main server: `Relay.Secret` in `management.json` (`OPENZRO_RELAY_AUTH_SECRET`). Every relay
  must use the same secret.

## Run a relay

The relay maps each command-line flag to an `OZ_` environment variable:

```yaml
services:
  relay:
    image: ghcr.io/openzro/relay:latest
    restart: unless-stopped
    ports:
      - "443:443/tcp"
      - "443:443/udp"
      - "80:80/tcp"
    environment:
      - OZ_LISTEN_ADDRESS=:443
      - OZ_EXPOSED_ADDRESS=rels://relay-us.example.com:443
      - OZ_AUTH_SECRET=<relay secret from management.json>
      - OZ_LETSENCRYPT_DOMAINS=relay-us.example.com
      - OZ_LETSENCRYPT_EMAIL=admin@example.com
      - OZ_LETSENCRYPT_DATA_DIR=/data/letsencrypt
      - OZ_LOG_LEVEL=info
    volumes:
      - relay-data:/data

volumes:
  relay-data:
```

Pin the image to the same version as your management server instead of `latest`. To use your own certificate, replace
the `OZ_LETSENCRYPT_*` variables with `OZ_TLS_CERT_FILE` and `OZ_TLS_KEY_FILE`. With TLS the relay also accepts QUIC on
the same UDP port.

Behind a reverse proxy, run the relay without TLS, forward the `/relay` path to it as WebSocket, and set
`OZ_EXPOSED_ADDRESS=rels://relay-us.example.com:443/relay`. QUIC cannot pass through an HTTP proxy.

Start it and check the log:

```bash
docker compose up -d
docker compose logs relay
```

You should see:
```
server will be available on: rels://relay-us.example.com:443
```

## Add the relays to management

On the main server, list every relay in `Relay.Addresses` in `management.json`:

```json
"Relay": {
  "Addresses": [
    "rels://relay-us.example.com:443",
    "rels://relay-eu.example.com:443"
  ],
  "CredentialsTTL": "24h",
  "Secret": "<relay secret>"
}
```

Keep the local relay's address in the list if you keep it running; otherwise remove the `relay` service from the main
`docker-compose.yml`. Then restart management:

```bash
docker compose restart management
```

Management reads `management.json` only at startup, and peers receive the new list on their next sync. Re-running
`configure.sh` rewrites `Relay.Addresses` from `OPENZRO_RELAY_ENDPOINT`; for a single external relay, set that variable
and `OPENZRO_RELAY_AUTH_SECRET` in `setup.env` instead of editing the file.

## How clients use several relays

Each client connects to all listed relays at the same time and keeps the first one that completes the connection as
its **home relay**. Peers on different home relays still reach each other: a client also connects to the other
peer's home relay when needed. If the home relay goes down, the client tries to reconnect to it and, if that fails,
picks a new one from the list. See [Multi-Region Relays](/selfhosted/maintenance/scaling/multi-region-relays) for
details.

## Verify

On a client, run `openzro status -d`. The **Relays** section lists the home relay, and peers connected through a relay
show `Connection type: Relayed` with the relay address.

To test a relay on purpose, start a client with `OZ_FORCE_RELAY=true` so it skips direct connections.
