# Set Up External Signal Server

This guide moves the `signal` service to its own machine, for example `signal.example.com`.

<Warning>
Clients read the Signal address when they connect. After you change it, peers keep using the old address until they
reconnect, for example with `openzro down && openzro up`. Keep the old signal running until every peer has
reconnected.
</Warning>

## Requirements

- A Linux machine with Docker and a public DNS name (`signal.example.com`).
- TCP port 443 open (or another port of your choice).

## Run Signal

Signal reads only its port from the environment (`OZ_PORT`); everything else is a command-line flag. With a Let's
Encrypt certificate:

```yaml
services:
  signal:
    image: ghcr.io/openzro/signal:latest
    restart: unless-stopped
    ports:
      - "443:443"
      - "80:80"   # Let's Encrypt HTTP challenge
    volumes:
      - signal-data:/var/lib/openzro
    command: [
      "--port", "443",
      "--letsencrypt-domain", "signal.example.com",
      "--log-file", "console",
      "--log-level", "info"
    ]

volumes:
  signal-data:
```

To use your own certificate instead, mount it and replace `--letsencrypt-domain` with
`--cert-file /certs/fullchain.pem --cert-key /certs/privkey.pem`. Behind a reverse proxy, forward
`/signalexchange.SignalExchange/` to the signal container as gRPC (h2c) and run signal without TLS on port 80.

Pin the image to the same version as your management server instead of `latest`.

## Point management at the new Signal

Edit `management.json` on the main server:

```json
"Signal": {
  "Proto": "https",
  "URI": "signal.example.com:443"
},
"Flow": {
  "Proto": "https",
  "URI": "openzro.example.com:33073"
}
```

`Flow` is where peers send traffic events. It defaults to the Signal address, but the flow service runs on the
management server, so set it to the management address (`OPENZRO_DOMAIN:OPENZRO_MGMT_API_PORT`) once Signal moves.

Then remove the `signal` service from the main `docker-compose.yml` and restart management:

```bash
docker compose up -d --remove-orphans
docker compose restart management
```

Re-running `configure.sh` restores the local signal and the old `Signal` address; repeat these edits afterwards.

## Verify

On a client, after `openzro down && openzro up`, run `openzro status -d` and check that **Signal** shows
`signal.example.com:443` as connected.

## Several Signal instances

Signal instances behind a load balancer must share a broker so a message reaches the instance the other peer is
connected to:

| Variables | Broker |
|---|---|
| `OPENZRO_SIGNAL_DISPATCHER=redis`, `OPENZRO_REDIS_URL=redis://...` | Redis, Valkey or Dragonfly |
| `OPENZRO_SIGNAL_DISPATCHER=nats`, `OPENZRO_NATS_URL=nats://...` | An external NATS server |
| `OPENZRO_BROKER=embedded`, `OPENZRO_CLUSTER_PEERS=nats://node2:6222,...` | NATS embedded in each signal instance |

Without these, signal uses an in-memory dispatcher and supports a single instance.
