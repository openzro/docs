# Migrate from SQLite to PostgreSQL

A default deployment keeps its data in three SQLite databases. Each can move to PostgreSQL separately:

| Data | Default location | How to move it |
|---|---|---|
| Management store (accounts, peers, policies, …) | `store.db` in the `management` container's `/var/lib/openzro` | `OPENZRO_STORE_CONFIG_ENGINE` and `OPENZRO_STORE_ENGINE_POSTGRES_DSN` in `setup.env` |
| Activity log | `events.db` in the same directory | `OZ_ACTIVITY_EVENT_STORE_ENGINE` and `OZ_ACTIVITY_EVENT_POSTGRES_DSN` on the `management` container |
| Embedded Dex | `dex.db` in the `dex` container's `/var/lib/dex` | `storage` in `dex.config.yaml` |

PostgreSQL is required to run several management instances against the same data.

<Warning>
Back up everything first, as described in [Backup](/selfhosted/maintenance/backup), and plan a maintenance window:
the management service must be stopped while its data is copied.
</Warning>

## Management store

Follow [Migrating from SQLite store to Postgres store](/selfhosted/postgres-store#migrating-from-sq-lite-store-to-postgres-store):
copy `store.db` out of the container, import it with `pgloader`, clean up orphaned rows, then set
`OPENZRO_STORE_CONFIG_ENGINE=postgres` and `OPENZRO_STORE_ENGINE_POSTGRES_DSN` in `setup.env` and re-run
`./configure.sh`.

The PostgreSQL server must be reachable from the `management` container: add it as a service to the compose file, or
use a host name the container can resolve.

## Activity log

1. Import `events.db` the same way:
```bash
docker compose cp management:/var/lib/openzro/events.db backup/events.db
pgloader --type sqlite backup/events.db "postgresql://<user>:<password>@<host>:5432/<activity_db>"
```
2. Add the activity store variables to the `environment` of the `management` service in `docker-compose.yml`. The
   generated file does not include them, so add them again after re-running `configure.sh`:
```yaml
      - OZ_ACTIVITY_EVENT_STORE_ENGINE=postgres
      - OZ_ACTIVITY_EVENT_POSTGRES_DSN=host=<host> port=5432 user=<user> password=<password> dbname=<activity_db>
```
3. Restart management and look for `using postgres as activity event store engine` in its logs.

See [Activity Events Postgres store](/selfhosted/activity-postgres-store) for details and rollback.

## Embedded Dex

Dex keeps sessions, refresh tokens, the connectors added in the dashboard, and local users created by
[SCIM](/manage/team/idp-sync) in its own database. To use PostgreSQL, change the `storage` section of
`artifacts/dex.config.yaml`:

```yaml
storage:
  type: postgres
  config:
    host: <host>
    port: 5432
    database: dex
    user: <user>
    password: <password>
    ssl:
      mode: require
```

Then restart Dex with `docker compose restart dex`. Re-running `configure.sh` resets `dex.config.yaml` from its
template, so repeat the edit afterwards.

<Note>
openZro does not migrate Dex's data between storage backends. After the switch, users log in again, and connectors
and SCIM-created local users that lived only in `dex.db` must be recreated. Connectors and the bootstrap admin defined
in `dex.config.yaml` itself are unaffected.
</Note>
