# Environment Variables Configuration

A self-hosted openZro deployment is configured in two places:

- **`setup.env`**, read by `configure.sh` when it renders `docker-compose.yml`, `management.json`,
  `dex.config.yaml` and `turnserver.conf`. Changes take effect only after you re-run `./configure.sh`.
- **Runtime environment variables** on the containers, read by the services when they start. Set them in the
  `environment` section of a service in `docker-compose.yml`. The generated file passes only a few of them, so add the
  others yourself, and add them again after re-running `configure.sh`.

For the generated files, see [Configuration Files](/selfhosted/configuration-files).

## setup.env

`setup.env.example` lists every variable with comments. The main ones:

### Domain and certificates

| Variable | Default | Description |
|---|---|---|
| `OPENZRO_DOMAIN` | – | Public domain of the deployment, e.g. `openzro.example.com`. |
| `OPENZRO_LETSENCRYPT_EMAIL` | – | Email for Let's Encrypt; the dashboard container obtains the certificate. |
| `OPENZRO_DISABLE_LETSENCRYPT` | `false` | Set `true` when a reverse proxy terminates TLS. See [External Reverse Proxy](/selfhosted/external-reverse-proxy). |

### Ports and endpoints

| Variable | Default | Description |
|---|---|---|
| `OPENZRO_MGMT_API_PORT` | `33073` | Public port of the management API and gRPC. |
| `OPENZRO_SIGNAL_PORT` | `10000` | Public port of signal. |
| `OPENZRO_RELAY_PORT` | `33080` | Port the relay listens on and announces. |
| `OPENZRO_RELAY_DOMAIN` | `OPENZRO_DOMAIN` | Domain announced for the relay. |
| `OPENZRO_RELAY_ENDPOINT` | `rel://<relay domain>:<relay port>` | Relay address handed to clients. |
| `OPENZRO_TURN_DOMAIN` | `OPENZRO_DOMAIN` | Domain of the Coturn server handed to clients. |
| `OPENZRO_TURN_EXTERNAL_IP` | discovered | Public IP Coturn announces. `configure.sh` looks it up if empty. |
| `TURN_MIN_PORT`, `TURN_MAX_PORT` | `49152`, `65535` | Coturn relay port range. |

### Management

| Variable | Default | Description |
|---|---|---|
| `OPENZRO_STORE_CONFIG_ENGINE` | `sqlite` | `sqlite`, `postgres` or `mysql`. |
| `OPENZRO_STORE_ENGINE_POSTGRES_DSN` | – | PostgreSQL DSN; required with `postgres`. |
| `OPENZRO_STORE_ENGINE_MYSQL_DSN` | – | MySQL DSN, e.g. `user:password@tcp(host:3306)/openzro`; required with `mysql`. |
| `OPENZRO_MGMT_SINGLE_ACCOUNT_MODE_DOMAIN` | `OPENZRO_DOMAIN` | All users join one account under this domain. |
| `OPENZRO_MGMT_DNS_DOMAIN` | `openzro.selfhosted` | DNS domain for peer names. |
| `OPENZRO_MGMT_DISABLE_DEFAULT_POLICY` | `false` | Do not create the all-to-all `Default` policy. |
| `OPENZRO_MGMT_IDP_SIGNKEY_REFRESH` | `false` | Refresh the IdP signing keys when they expire. |
| `OPENZRO_DISABLE_ANONYMOUS_METRICS` | `false` | Disable anonymous usage metrics. |

### Identity provider

With the embedded Dex (the default), `configure.sh` fills in the `OPENZRO_AUTH_*` endpoints itself.

| Variable | Description |
|---|---|
| `OPENZRO_DEX_ADMIN_EMAIL` | Email of the bootstrap admin. |
| `OPENZRO_DEX_ADMIN_PASSWORD_BCRYPT` | Bcrypt hash of the admin password. If empty, `configure.sh` generates a password and prints it once. |
| `OPENZRO_DEX_TAG` | Dex image tag. |

For an [external IdP](/selfhosted/identity-providers), set at least:

| Variable | Description |
|---|---|
| `OPENZRO_AUTH_OIDC_CONFIGURATION_ENDPOINT` | The IdP's discovery URL. Setting it switches `configure.sh` to the external IdP. |
| `OPENZRO_AUTH_CLIENT_ID`, `OPENZRO_AUTH_CLIENT_SECRET` | The OIDC client for the dashboard and clients. |
| `OPENZRO_AUTH_AUDIENCE` | Expected token audience. |
| `OPENZRO_AUTH_SUPPORTED_SCOPES` | Scopes to request, e.g. `openid profile email offline_access`. Required; the dashboard refuses to start without it. |
| `OPENZRO_AUTH_USER_ID_CLAIM` | Claim used as the user ID (default `sub`). |
| `OPENZRO_AUTH_DEVICE_AUTH_PROVIDER`, `OPENZRO_AUTH_DEVICE_AUTH_CLIENT_ID` | Device-code login for clients without a browser. |
| `OPENZRO_MGMT_IDP`, `OPENZRO_IDP_MGMT_CLIENT_ID`, `OPENZRO_IDP_MGMT_CLIENT_SECRET` | Optional API access to the IdP, to show user names and emails. |

### Image tags

`OPENZRO_DASHBOARD_TAG`, `OPENZRO_SIGNAL_TAG`, `OPENZRO_RELAY_TAG`, `OPENZRO_MANAGEMENT_TAG` and `COTURN_TAG` pin the images.

## Management runtime variables

The management binary takes its settings from `management.json` and its command-line flags. It does not map
`OZ_`-prefixed variables to flags. These variables are read directly:

### Storage and identity

| Variable | Description |
|---|---|
| `OPENZRO_STORE_ENGINE_POSTGRES_DSN`, `OPENZRO_STORE_ENGINE_MYSQL_DSN` | DSN of the management store (passed by the generated compose file). |
| `OZ_ACTIVITY_EVENT_STORE_ENGINE` | Activity log store: `sqlite` (default), `postgres` or `mysql`. |
| `OZ_ACTIVITY_EVENT_POSTGRES_DSN`, `OZ_ACTIVITY_EVENT_MYSQL_DSN` | DSN of the activity log store. |
| `OZ_SQL_MAX_OPEN_CONNS` | Maximum open database connections. |
| `OZ_EVENT_ACTIVITY_LOG_ENABLED` | Set `false` to stop recording the activity log (default on). |
| `OPENZRO_MGMT_WG_PRIVATE_KEY` | Management's WireGuard identity; several replicas must share it. Overrides `WgPrivateKey`. |
| `OPENZRO_DASHBOARD_URL` | Public dashboard URL, used in links such as [2FA on device sign-in](/manage/settings/multi-factor-authentication). |

### Embedded Dex

Passed by the generated compose file.

| Variable | Description |
|---|---|
| `OPENZRO_DEX_GRPC_ADDR` | Dex gRPC API, `dex:5557`. |
| `OPENZRO_DEX_GRPC_CA_CERT`, `OPENZRO_DEX_GRPC_CLIENT_CERT`, `OPENZRO_DEX_GRPC_CLIENT_KEY` | mTLS certificates from `grpc-certs/`. |
| `OPENZRO_DEX_GRPC_INSECURE` | Connect without TLS (development only). |
| `OPENZRO_SCIM_LOCAL_USERS_ENABLED` | Allow SCIM to create local Dex users. |

### Several management replicas

| Variable | Description |
|---|---|
| `OPENZRO_BROKER`, `OPENZRO_REDIS_URL`, `OPENZRO_NATS_URL`, `OPENZRO_CLUSTER_PEERS` | Shared broker that replicas use to coordinate. See [High availability](/selfhosted/kubernetes/high-availability). |
| `OZ_IDP_CACHE_REDIS_ADDRESS` | Redis URL for a shared IdP user cache. |

### Activity streaming and traffic events

| Prefix | Description |
|---|---|
| `OPENZRO_ACTIVITY_EXPORT_*` | Stream the audit log. See [Event streaming](/manage/activity/event-streaming). |
| `OPENZRO_FLOW_STORE_ENGINE`, `OPENZRO_FLOW_STORE_DSN`, `OPENZRO_FLOW_RETENTION` | Store traffic events. See [Flow Events Store](/selfhosted/flow-events-store). |
| `OPENZRO_FLOW_EXPORT_*` | Export traffic events to Elasticsearch, Datadog or HTTP. |

### Flow archive (cold storage)

Written by the management server's archive sink and read back by the
dashboard's network-traffic view. Full guides:
[GCS](/selfhosted/flow-archive-gcs) and
[Compaction](/selfhosted/flow-archive-compaction).

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENZRO_FLOW_ARCHIVE_FORMAT` | `ndjson` | `parquet` or `ndjson`. **Set `parquet`** — the `ndjson` default is write-only and cannot be read from the dashboard or compacted. |

**Google Cloud Storage**

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENZRO_FLOW_ARCHIVE_GCS_BUCKET` | - | Destination bucket. Enables the sink. |
| `OPENZRO_FLOW_ARCHIVE_GCS_PREFIX` | - | Key prefix. |
| `OPENZRO_FLOW_ARCHIVE_GCS_PROJECT_ID` | - | Informational. |
| `OPENZRO_FLOW_ARCHIVE_GCS_CREDENTIALS_FILE` | - | Service-account JSON path, for writes and deletes. |
| `OPENZRO_FLOW_ARCHIVE_GCS_CREDENTIALS_JSON` | - | The same credential inline. |
| `OPENZRO_FLOW_ARCHIVE_GCS_HMAC_KEY_ID` | - | HMAC interoperability key. Required for **reads** — DuckDB rejects service-account JSON. |
| `OPENZRO_FLOW_ARCHIVE_GCS_HMAC_SECRET` | - | Secret for the HMAC key above. |
| `OPENZRO_FLOW_ARCHIVE_GCS_ENDPOINT` | - | Override the storage endpoint. |
| `OPENZRO_FLOW_ARCHIVE_GCS_FLUSH_INTERVAL` | `15m` | Forces a rotation once buffered data is this stale. |
| `OPENZRO_FLOW_ARCHIVE_GCS_MAX_EVENTS_PER_FILE` | `100000` | Rotates after this many events. |
| `OPENZRO_FLOW_ARCHIVE_GCS_BUFFER_SIZE` | `50000` | In-memory queue capacity. |

**S3 and S3-compatible**

| Variable | Default | Description |
|----------|---------|-------------|
| `OPENZRO_FLOW_ARCHIVE_S3_BUCKET` | - | Destination bucket. Enables the sink. |
| `OPENZRO_FLOW_ARCHIVE_S3_PREFIX` | - | Key prefix. |
| `OPENZRO_FLOW_ARCHIVE_S3_REGION` | - | Bucket region. |
| `OPENZRO_FLOW_ARCHIVE_S3_ENDPOINT` | - | Custom endpoint (MinIO, R2, GCS interop). |
| `OPENZRO_FLOW_ARCHIVE_S3_ACCESS_KEY` | - | Signs reads, writes and deletes alike. |
| `OPENZRO_FLOW_ARCHIVE_S3_SECRET_KEY` | - | Secret for the key above. |
| `OPENZRO_FLOW_ARCHIVE_S3_FLUSH_INTERVAL` | `15m` | As per GCS. |
| `OPENZRO_FLOW_ARCHIVE_S3_MAX_EVENTS_PER_FILE` | `100000` | As per GCS. |
| `OPENZRO_FLOW_ARCHIVE_S3_BUFFER_SIZE` | `50000` | As per GCS. |

**Read path (DuckDB)**

Tuning for archive queries. Raise the limits before assuming a slow
cold query needs more compaction.

| Variable | Description |
|----------|-------------|
| `OPENZRO_FLOW_ARCHIVE_QUERY_TIMEOUT` | Per-query deadline. |
| `OPENZRO_FLOW_ARCHIVE_MEMORY_LIMIT` | DuckDB memory ceiling. |
| `OPENZRO_FLOW_ARCHIVE_THREADS` | DuckDB worker threads. |
| `OPENZRO_FLOW_ARCHIVE_MAX_CONCURRENT_QUERIES` | Archive queries served at once. |

### Tuning

| Variable | Default | Description |
|---|---|---|
| `OPENZRO_ADMISSION_REVALIDATE_INTERVAL_SECONDS` | `60` | How often [Device Admission](/manage/access-control/posture-checks/device-admission) re-checks connected peers. |
| `OPENZRO_ADMISSION_BYPASS_SWEEP_INTERVAL_SECONDS` | `3600` | How often expired admission bypasses are cleaned up. |
| `OPENZRO_PEER_UPDATE_CHANNEL_BUFFER_SIZE` | `1000` | Queued network-map updates per peer before updates are dropped. |
| `OPENZRO_PEER_UPDATE_FANOUT_CONCURRENCY` | `64` | Peers updated in parallel when the network changes. |
| `OPENZRO_PEER_STREAM_RECONCILE_INTERVAL_SECONDS` | – | How often each replica reconciles its client streams with the stored peer state. |
| `OZ_GET_ACCOUNT_BUFFER_INTERVAL` | – | Window for batching account reads (Go duration). |
| `OPENZRO_METRICS_INTERVAL_IN_SECONDS` | – | Interval of the anonymous metrics push. |

## Relay runtime variables

The relay maps every flag to an `OZ_` variable (`--listen-address` → `OZ_LISTEN_ADDRESS`).

| Variable | Default | Description |
|---|---|---|
| `OZ_LISTEN_ADDRESS` | `:443` | Listen address. The generated compose file sets `:$OPENZRO_RELAY_PORT`. |
| `OZ_EXPOSED_ADDRESS` | – | Address announced to clients, e.g. `rels://relay.example.com:443/relay`. |
| `OZ_AUTH_SECRET` | – | Shared secret; must match `Relay.Secret` in `management.json`. |
| `OZ_METRICS_PORT` | `9090` | Prometheus metrics port. |
| `OZ_TLS_CERT_FILE`, `OZ_TLS_KEY_FILE` | – | TLS certificate. With TLS, the relay also accepts QUIC. |
| `OZ_LETSENCRYPT_DOMAINS`, `OZ_LETSENCRYPT_EMAIL`, `OZ_LETSENCRYPT_DATA_DIR` | – | Obtain a certificate from Let's Encrypt. |
| `OZ_LETSENCRYPT_AWS_ROUTE53` | `false` | Use the Route 53 DNS challenge. |
| `OZ_LOG_LEVEL`, `OZ_LOG_FILE` | `info`, `console` | Logging. |
| `OZ_CLUSTER_HEADLESS`, `OZ_CLUSTER_PORT`, `OZ_POD_IP`, `OZ_CLUSTER_AUTH_SECRET`, `OZ_CLUSTER_LOOKUP_TIMEOUT` | – | Multi-pod relay on Kubernetes ([ADR-0014](https://github.com/openzro/openzro/blob/main/docs/adr/0014-coordinated-multi-pod-relay.md)). |

## Signal runtime variables

Signal reads `OZ_PORT` (its listen port) from the environment. Its other settings are command-line flags. With
several signal replicas, set the same `OPENZRO_BROKER` / `OPENZRO_REDIS_URL` / `OPENZRO_NATS_URL` as management.

## All services

| Variable | Description |
|---|---|
| `OZ_LOG_FORMAT` | Log format: `json`, `syslog`, or text (default). |
| `OZ_LOG_MAX_SIZE_MB` | Log file size in MB before rotation (default 15). |

## Dashboard

The dashboard container gets its settings from the compose file, rendered from `setup.env`: the `AUTH_*` OIDC
settings, `OPENZRO_MGMT_API_ENDPOINT` and `OPENZRO_MGMT_GRPC_API_ENDPOINT`, and `LETSENCRYPT_DOMAIN` /
`LETSENCRYPT_EMAIL` for its certbot. You can add `AUTH_EXTRA_OIDC_DOMAINS` to list additional domains the login flow may call.

## Coturn

Coturn is configured through `turnserver.conf`, rendered from `TURN_USER`, `TURN_PASSWORD` (generated),
`TURN_MIN_PORT`, `TURN_MAX_PORT` and `OPENZRO_TURN_EXTERNAL_IP`. It listens on UDP 3478, TLS 5349 and the relay port
range on the host network.
