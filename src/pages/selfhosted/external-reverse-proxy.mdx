# External Reverse Proxy Setup for Self-Hosted openZro

By default, the stack generated by `configure.sh` publishes each service on its own port and the dashboard container
obtains a Let's Encrypt certificate itself. If you already run a reverse proxy, you can put openZro behind it and serve
everything on port 443 instead.

Your reverse proxy must support **HTTP/2 and gRPC** (management and signal) and **WebSocket** (relay).

## How it fits together

| Path | Protocol | Target (Docker service:port) |
|---|---|---|
| `/` | HTTP | `dashboard:80` |
| `/api` | HTTP | `management:443` |
| `/management.ManagementService/` | gRPC (h2c) | `management:443` |
| `/signalexchange.SignalExchange/` | gRPC (h2c) | `signal:80` |
| `/relay` | WebSocket | `relay:443` |
| `/dex/` | HTTP | `dex:5556` — keep the `/dex` prefix, do not strip it |

Coturn is not proxied: it keeps using UDP 3478 and its relay port range directly on the host.

<Note>
    Forward `/dex/` unchanged. Dex serves its routes and assets under the path of its issuer
    (`https://<your-domain>/dex`), so a proxy that strips the prefix breaks the login pages. The `nginx.tmpl.conf` and
    `docker-compose.yml.tmpl.traefik` examples in the repository still strip it
    ([openzro#246](https://github.com/openzro/openzro/issues/246)).
</Note>

The relay also listens for QUIC on the same port, which an HTTP reverse proxy cannot forward. Behind a proxy, clients
use the relay's WebSocket transport.

## Step 1: Configure setup.env

Disable the built-in certificate handling and announce every service on port 443:

```bash
OPENZRO_DISABLE_LETSENCRYPT=true
OPENZRO_MGMT_API_PORT=443
OPENZRO_SIGNAL_PORT=443
OPENZRO_RELAY_PORT=443
```

Then run `./configure.sh`. With Let's Encrypt disabled, it prints the forwards your proxy needs. The endpoints that
management hands to clients become `https://<your-domain>:443` for management and signal and
`rels://<your-domain>:443/relay` for the relay.

## Step 2: Adjust docker-compose.yml

The generated `artifacts/docker-compose.yml` still publishes host ports for `dashboard` (80 and 443), `management`,
`signal` and `relay`. Your proxy needs 80 and 443, so:

- remove the `ports:` sections of `dashboard`, `management`, `signal` and `relay`;
- attach the proxy to the same Docker network as these services, so it can reach them by service name. If your proxy
  runs on the host instead, publish each service on a localhost port (for example `127.0.0.1:8080:80` for the
  dashboard) and point the proxy at those ports.

Leave `coturn` unchanged. Re-running `configure.sh` overwrites `docker-compose.yml`, so repeat this step after each
run.

## Configuration templates

The examples use `openzro.example.com` and the Docker service names. Replace them with your domain and, for a proxy on
the host, with the localhost ports you published.

### Nginx

```nginx
upstream dashboard  { server dashboard:80; keepalive 10; }
upstream management { server management:443; }
upstream signal     { server signal:80; }
upstream relay      { server relay:443; }
upstream dex        { server dex:5556; }

server {
    listen 80;
    server_name openzro.example.com;
    location / { return 301 https://$host$request_uri; }
}

server {
    listen 443 ssl http2;
    server_name openzro.example.com;

    ssl_certificate     /etc/ssl/certs/openzro.example.com/fullchain.pem;
    ssl_certificate_key /etc/ssl/certs/openzro.example.com/privkey.pem;

    # Keep long-lived gRPC streams open
    client_header_timeout 1d;
    client_body_timeout 1d;

    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto https;
    proxy_set_header X-Forwarded-Host $host;
    grpc_set_header  X-Forwarded-For $proxy_add_x_forwarded_for;

    location / {
        proxy_pass http://dashboard;
    }

    location /api {
        proxy_pass http://management;
    }

    location /management.ManagementService/ {
        grpc_pass grpc://management;
        grpc_read_timeout 1d;
        grpc_send_timeout 1d;
        grpc_socket_keepalive on;
    }

    location /signalexchange.SignalExchange/ {
        grpc_pass grpc://signal;
        grpc_read_timeout 1d;
        grpc_send_timeout 1d;
        grpc_socket_keepalive on;
    }

    location /relay {
        proxy_pass http://relay;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 1d;
        proxy_send_timeout 1d;
    }

    location /dex/ {
        proxy_pass http://dex;
    }
}
```

`proxy_pass http://dex;` without a trailing path forwards the request URI unchanged, keeping the `/dex` prefix.

For the certificate, use any ACME client, for example `certbot --nginx -d openzro.example.com`.

### Traefik

Add labels to the services in `docker-compose.yml`. This assumes an entrypoint named `websecure` on 443 and a
certificate resolver named `letsencrypt`:

```yaml
  dashboard:
    labels:
      - traefik.enable=true
      - traefik.http.routers.openzro-dashboard.rule=Host(`openzro.example.com`)
      - traefik.http.routers.openzro-dashboard.entrypoints=websecure
      - traefik.http.routers.openzro-dashboard.tls.certresolver=letsencrypt
      - traefik.http.routers.openzro-dashboard.priority=1
      - traefik.http.services.openzro-dashboard.loadbalancer.server.port=80

  management:
    labels:
      - traefik.enable=true
      - traefik.http.routers.openzro-api.rule=Host(`openzro.example.com`) && PathPrefix(`/api`)
      - traefik.http.routers.openzro-api.entrypoints=websecure
      - traefik.http.routers.openzro-api.tls.certresolver=letsencrypt
      - traefik.http.routers.openzro-api.service=openzro-api
      - traefik.http.services.openzro-api.loadbalancer.server.port=443
      - traefik.http.routers.openzro-mgmt-grpc.rule=Host(`openzro.example.com`) && PathPrefix(`/management.ManagementService/`)
      - traefik.http.routers.openzro-mgmt-grpc.entrypoints=websecure
      - traefik.http.routers.openzro-mgmt-grpc.tls.certresolver=letsencrypt
      - traefik.http.routers.openzro-mgmt-grpc.service=openzro-mgmt-grpc
      - traefik.http.services.openzro-mgmt-grpc.loadbalancer.server.port=443
      - traefik.http.services.openzro-mgmt-grpc.loadbalancer.server.scheme=h2c

  signal:
    labels:
      - traefik.enable=true
      - traefik.http.routers.openzro-signal.rule=Host(`openzro.example.com`) && PathPrefix(`/signalexchange.SignalExchange/`)
      - traefik.http.routers.openzro-signal.entrypoints=websecure
      - traefik.http.routers.openzro-signal.tls.certresolver=letsencrypt
      - traefik.http.services.openzro-signal.loadbalancer.server.port=80
      - traefik.http.services.openzro-signal.loadbalancer.server.scheme=h2c

  relay:
    labels:
      - traefik.enable=true
      - traefik.http.routers.openzro-relay.rule=Host(`openzro.example.com`) && PathPrefix(`/relay`)
      - traefik.http.routers.openzro-relay.entrypoints=websecure
      - traefik.http.routers.openzro-relay.tls.certresolver=letsencrypt
      - traefik.http.services.openzro-relay.loadbalancer.server.port=443

  dex:
    labels:
      - traefik.enable=true
      - traefik.http.routers.openzro-dex.rule=Host(`openzro.example.com`) && PathPrefix(`/dex/`)
      - traefik.http.routers.openzro-dex.entrypoints=websecure
      - traefik.http.routers.openzro-dex.tls.certresolver=letsencrypt
      - traefik.http.services.openzro-dex.loadbalancer.server.port=5556
```

Traefik keeps gRPC streams open by default. If you set `respondingTimeouts` on the entrypoint, set `readTimeout` to
`0` or the streams are cut.

### Caddy

```
openzro.example.com {
    reverse_proxy /api* management:443
    reverse_proxy /management.ManagementService/* h2c://management:443
    reverse_proxy /signalexchange.SignalExchange/* h2c://signal:80
    reverse_proxy /relay* relay:443
    reverse_proxy /dex/* dex:5556
    reverse_proxy /* dashboard:80
}
```

Caddy obtains the certificate and handles WebSocket upgrades automatically.

### Nginx Proxy Manager

Create a proxy host for `openzro.example.com` that forwards to `dashboard:80`, enable **Websockets Support** and
**HTTP/2 Support** on its SSL tab, and add this to **Advanced → Custom Nginx Configuration**:

```nginx
client_header_timeout 1d;
client_body_timeout 1d;

location /api {
    proxy_pass http://management:443;
}

location /management.ManagementService/ {
    grpc_pass grpc://management:443;
    grpc_read_timeout 1d;
    grpc_send_timeout 1d;
    grpc_socket_keepalive on;
}

location /signalexchange.SignalExchange/ {
    grpc_pass grpc://signal:80;
    grpc_read_timeout 1d;
    grpc_send_timeout 1d;
    grpc_socket_keepalive on;
}

location /relay {
    proxy_pass http://relay:443;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_read_timeout 1d;
}

location /dex/ {
    proxy_pass http://dex:5556;
}
```

Nginx Proxy Manager must be on the same Docker network as the openZro services.

## Troubleshooting

### gRPC connections failing

Clients fail to log in or sync, and the management or signal logs show nothing:
- Check that the proxy speaks HTTP/2 to clients and gRPC (h2c) to `management` and `signal`.
- Check the read timeouts. Management and signal keep streams open for hours; a 60-second default cuts them.

### Relay connections failing

`openzro status -d` shows peers on relay failing to connect:
- Check that `/relay` is forwarded with WebSocket upgrade headers.
- Check that the relay endpoint handed to clients is `rels://<your-domain>:443/relay`; if not, re-run `configure.sh`
  with `OPENZRO_RELAY_PORT=443`.

### Login page broken or 404 at /dex

- Check that `/dex/` reaches `dex:5556` with the `/dex` prefix intact.
- Check that `https://<your-domain>/dex/.well-known/openid-configuration` returns JSON.

### Dashboard loads but API calls fail

- Check that `/api` is forwarded to `management:443` over plain HTTP.
- Check that `OPENZRO_MGMT_API_PORT=443` was set before running `configure.sh`; the dashboard calls the management
  endpoint it was given.
