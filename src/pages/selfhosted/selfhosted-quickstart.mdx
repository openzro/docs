# Self-Hosting Quickstart Guide (5 min)

openZro is open source and can be self-hosted on your servers. If you would like to learn more about the architecture please refer to the [Architecture section](/about-openzro/how-openzro-works).

<Note>
This is the quickest way to try self-hosted openZro. It should take around 5 minutes to get started if you already have a public domain and a VM.
</Note>

## Infrastructure requirements
- A Linux VM with at least **1CPU** and **2GB** of memory.
- The VM must be publicly accessible on **TCP ports 80 and 443**, and **UDP port 3478**.
- A **public domain** name that resolves to the VM's public IP address (e.g. `openzro.example.com`).

## Software requirements

- Docker with docker-compose plugin ([Docker installation guide](https://docs.docker.com/engine/install/)) or Docker with docker-compose version 2 or higher
- [jq](https://jqlang.github.io/jq/) - install with `sudo apt install jq` or `sudo yum install jq`
- [curl](https://curl.se/) - install with `sudo apt install curl` or `sudo yum install curl`

## Installation Script

The install script today is the Zitadel-based flow inherited from
upstream — it provisions a [Zitadel](https://zitadel.com/) IdP next
to the management server and wires the OIDC trust between them, so
you can sign in immediately without configuring an external
provider.

Download and run it:

```bash
curl -fsSL \
  https://github.com/openzro/openzro/releases/latest/download/getting-started-with-zitadel.sh \
  | bash
```

The script will:

1. Ask for your domain (e.g. `openzro.example.com`).
2. Pull the openZro images, generate `docker-compose.yml`,
   `management.json`, the Zitadel config, and a Caddy reverse proxy
   that handles Let's Encrypt automatically.
3. Bring everything up with `docker compose`.
4. Print the admin credentials for the new Zitadel IdP and the
   openZro dashboard URL.

Once finished, you can manage the resources via `docker compose`.
For details on the generated files and how to customize the
install, see [Configuration files](/selfhosted/configuration-files).

<Note>
    A simpler install flow that bundles the embedded Dex IdP (no
    Zitadel needed) and offers reverse-proxy + openZro Proxy choices
    is on the roadmap — see
    [docs/ROADMAP.md](https://github.com/openzro/openzro/blob/main/docs/ROADMAP.md).
    Until then, the Zitadel-based script above is the supported
    quickstart, and you can swap to a different IdP afterwards by
    following the [Identity Providers](/selfhosted/identity-providers)
    guide.
</Note>

### CNAME Record for Wildcard Subdomains (Optional)

If you'll later use the openZro Proxy to expose internal services
under subdomains (e.g. `app.openzro.example.com`), set a wildcard
CNAME on top of the A record for the management host:

| Type | Name | Content | Proxy status (Cloudflare) |
|------|------|---------|--------------|
| A | `openzro` | `YOUR.SERVER.IP.ADDRESS` | DNS only |
| CNAME | `*.openzro` | `openzro.example.com` | DNS only |

This wildcard CNAME is **not required for the openZro core
deployment** — it only matters if you later layer your own reverse
proxy in front of the management server to expose internal services
under subdomains. See [External Reverse Proxy](/selfhosted/external-reverse-proxy)
when you reach that stage.

### Initial setup (Onboarding)

When the script finishes it prints two pieces of information you'll
use to sign in for the first time:

- The **dashboard URL** (`https://openzro.example.com`)
- The **bootstrap admin credentials** for the bundled Zitadel IdP
  (a randomly-generated email + password the script provisioned
  for you)

1. Open the dashboard URL in your browser.
2. You'll be redirected to the Zitadel login page.
3. Sign in with the bootstrap credentials the script printed.
4. The first sign-in lands you in the dashboard with admin
   permissions; from **Settings → Users** you can add additional
   accounts or wire up an external IdP.

<Note>
Save the bootstrap credentials from the script output before
closing the terminal — the script doesn't store them anywhere
else. If you lose them, the recovery path is to redeploy from
scratch (the data lives in `docker compose` volumes; remove them
to start clean) or to reset the Zitadel admin via Zitadel's own
admin console at `https://openzro.example.com/ui/console`.
</Note>

## Troubleshoot

- **I lost the bootstrap admin credentials the script printed**

  They're not stored anywhere else. Easiest path: open Zitadel's
  own admin console at `https://openzro.example.com/ui/console`
  and reset via Zitadel's password-recovery flow (it sends an
  email if SMTP is configured). If you can't recover that way,
  redeploy from scratch — `docker compose down -v` removes the
  volumes and the next run of the install script provisions a
  fresh admin.

- **I forgot a user password (not the bootstrap admin)**

  Have an existing admin reset it via **Settings → Users** in the
  dashboard, or via the management API with a Personal Access
  Token.

- **SSO provider not appearing on login page**

  Check that the connector is properly configured in **Settings** → **Identity Providers**. Ensure the redirect URL is correctly configured in your IdP.

For more troubleshooting help, see the [Troubleshooting guide](/selfhosted/troubleshooting).
