# Switching from an External IdP to the Embedded Dex

New deployments use the embedded [Dex](https://dexidp.io/) by default: a `dex` container that issues tokens for
openZro and can federate to upstream identity providers through connectors. Deployments set up with an external IdP
connected directly (Keycloak, Zitadel, Okta, Entra ID and others) can switch to Dex, keeping the same IdP as a Dex
connector so users log in with the same credentials.

<Warning>
openZro has no migration tool for this switch, and **users are not carried over**. openZro identifies users by the
`sub` claim of their token. With Dex in between, the `sub` is a different value that encodes the connector and the
upstream user ID, so every user is treated as a new user on their first login through Dex. Their old user records,
roles, group memberships, access tokens and peer ownership stay attached to the old IDs.
</Warning>

Plan the switch as a cutover:

- after it, assign roles and groups again (or let [JWT group sync](/how-to/jwt-groups) do it);
- users log in again on their devices;
- service users and their access tokens are not affected, because they do not come from the IdP.

## Steps

1. **Back up** the deployment as described in [Backup](/selfhosted/maintenance/backup).

2. **Switch `configure.sh` to the embedded Dex.** In `setup.env`, remove or empty
   `OPENZRO_AUTH_OIDC_CONFIGURATION_ENDPOINT` and the other `OPENZRO_AUTH_*` values that pointed at your IdP. With
   that endpoint unset, `configure.sh` points every auth setting at `https://<your-domain>/dex` and renders
   `dex.config.yaml` with a bootstrap admin account. Copy `artifacts/management.json` to the `infrastructure_files`
   directory first, so the datastore encryption key is kept
   ([openzro#247](https://github.com/openzro/openzro/issues/247)), then run `./configure.sh`.

3. **Make sure `/dex` is reachable.** Dex must be served at `https://<your-domain>/dex` with the `/dex` prefix intact;
   see [External Reverse Proxy](/selfhosted/external-reverse-proxy) and
   [openzro#246](https://github.com/openzro/openzro/issues/246).

4. **Recreate the stack** with `docker compose up -d` in `artifacts/`. Management now accepts tokens only from Dex:
   tokens from the old IdP are rejected.

5. **Add your IdP as a connector.** Log in with the bootstrap admin printed by `configure.sh`, go to
   **Settings → Auth Providers**, and add your IdP. In the IdP, register the redirect URI
   `https://<your-domain>/dex/callback`. The provider pages under [Identity Providers](/selfhosted/identity-providers)
   describe each one.

6. **Re-assign roles and groups** as users log in again.

## Rolling back

To go back to the external IdP, restore `setup.env`, `management.json` and the management data from the backup, re-run
`./configure.sh`, and recreate the stack. Users who logged in through Dex in the meantime remain as extra user records.
