# Configuration Files Reference

`configure.sh` reads `setup.env` and renders the files below into `infrastructure_files/artifacts/`. Each run keeps the
previous `docker-compose.yml`, `management.json` and `turnserver.conf` as `<file>.bkp.<timestamp>`.

| File | Used by | Purpose |
|---|---|---|
| `docker-compose.yml` | Docker Compose | The services, images, ports and volumes |
| `management.json` | `management` | Management server configuration |
| `dex.config.yaml` | `dex` | Embedded Dex identity provider |
| `turnserver.conf` | `coturn` | STUN/TURN server |
| `grpc-certs/` | `management`, `dex` | mTLS certificates for the management ↔ Dex gRPC channel |
| `web/themes/openzro/` | `dex` | openZro theme for the Dex login pages |
| `openid-configuration.json` | `configure.sh` | Discovery document of an external IdP (only with an external IdP) |

For the variables in `setup.env`, see [Environment Variables](/selfhosted/environment-variables).

<Warning>
    Edit `setup.env` and re-run `configure.sh` rather than editing the generated files: a re-run overwrites them. Before
    re-running, copy `artifacts/management.json` to `infrastructure_files/` so the datastore encryption key is kept
    ([openzro#247](https://github.com/openzro/openzro/issues/247)).
</Warning>

## docker-compose.yml

| Service | Image | Ports (host:container) | Volume |
|---|---|---|---|
| `dex` | `ghcr.io/dexidp/dex:$OPENZRO_DEX_TAG` | none | `openzro-dex` → `/var/lib/dex` |
| `dashboard` | `ghcr.io/openzro/dashboard` | `80:80`, `443:443` | `openzro-letsencrypt` → `/etc/letsencrypt` |
| `signal` | `ghcr.io/openzro/signal` | `$OPENZRO_SIGNAL_PORT:80` (10000) | `openzro-signal` → `/var/lib/openzro` |
| `relay` | `ghcr.io/openzro/relay` | `$OPENZRO_RELAY_PORT` (33080) | none |
| `management` | `ghcr.io/openzro/management` | `$OPENZRO_MGMT_API_PORT:443` (33073) | `openzro-mgmt` → `/var/lib/openzro` |
| `coturn` | `coturn/coturn` | host network: 3478, 5349, UDP 49152-65535 | none |

The image tags come from `OPENZRO_*_TAG` in `setup.env`. Docker Compose prefixes volume names with the project name,
which is the directory name (`artifacts` by default).

The dashboard container obtains the Let's Encrypt certificate for `OPENZRO_DOMAIN` with certbot and serves the
dashboard on 443. Management reads the same certificate from the shared `openzro-letsencrypt` volume to serve its API
and gRPC on 33073.

The `management` service runs with these flags:

```yaml
command: [
  "--port", "443",
  "--log-file", "console",
  "--log-level", "info",
  "--disable-anonymous-metrics=$OPENZRO_DISABLE_ANONYMOUS_METRICS",
  "--single-account-mode-domain=$OPENZRO_MGMT_SINGLE_ACCOUNT_MODE_DOMAIN",
  "--dns-domain=$OPENZRO_MGMT_DNS_DOMAIN"
]
```

Other management flags you can add here include `--disable-single-account-mode`, `--disable-geolite-update`,
`--maxmind-license-key`, `--user-delete-from-idp` and `--metrics-port` (default 9090). The management binary does not
read its flags from environment variables.

The repository also contains `nginx.tmpl.conf` and `docker-compose.yml.tmpl.traefik`. `configure.sh` does not render
them; they are starting points for running behind a reverse proxy. See
[External Reverse Proxy](/selfhosted/external-reverse-proxy).

## management.json

Mounted at `/etc/openzro/management.json` in the `management` container.

### Connectivity

```json
"Stuns": [
  { "Proto": "udp", "URI": "stun:openzro.example.com:3478" }
],
"TURNConfig": {
  "Turns": [
    { "Proto": "udp", "URI": "turn:openzro.example.com:3478", "Username": "self", "Password": "<generated>" }
  ],
  "CredentialsTTL": "12h",
  "Secret": "secret",
  "TimeBasedCredentials": false
},
"Relay": {
  "Addresses": ["rel://openzro.example.com:33080"],
  "CredentialsTTL": "24h",
  "Secret": "<generated>"
},
"Signal": {
  "Proto": "http",
  "URI": "openzro.example.com:10000"
}
```

| Field | Description |
|---|---|
| `Stuns` | STUN servers handed to clients for NAT discovery. |
| `TURNConfig` | TURN servers for the ICE fallback, with static credentials or, with `TimeBasedCredentials`, credentials derived from `Secret`. |
| `Relay.Addresses` | openZro Relay endpoints handed to clients. Several addresses are allowed; clients pick the first that answers. |
| `Relay.Secret` | Shared secret the relay uses to check client tokens; must match the relay's `OZ_AUTH_SECRET`. |
| `Signal` | Signal endpoint handed to clients. |
| `Flow` | Optional endpoint for traffic events. Defaults to the Signal URI. |

### Authentication

| Field | Description |
|---|---|
| `HttpConfig.AuthIssuer` | OIDC issuer. With the embedded Dex: `https://<your-domain>/dex`. |
| `HttpConfig.AuthAudience` | Expected audience of access tokens. |
| `HttpConfig.ExtraAuthAudience` | An additional accepted audience. |
| `HttpConfig.AuthKeysLocation` | JWKS URL used to verify tokens. |
| `HttpConfig.AuthUserIDClaim` | Claim used as the user ID (default `sub`). |
| `HttpConfig.OIDCConfigEndpoint` | OIDC discovery URL. |
| `HttpConfig.IdpSignKeyRefreshEnabled` | Refresh signing keys when the cache headers say they expire. |
| `HttpConfig.CertFile`, `HttpConfig.CertKey` | TLS certificate for the API and gRPC port. |
| `HttpConfig.DashboardURL` | Public dashboard URL, used in links the server generates. |
| `IdpManagerConfig` | Optional API access to an external IdP, to show user names and emails. |
| `DeviceAuthorizationFlow` | Device-code login (`openzro up` on machines without a browser). |
| `PKCEAuthorizationFlow` | Browser login for the clients: authorization and token endpoints, client ID, scopes and redirect URLs. |

### Storage and identity

| Field | Description |
|---|---|
| `StoreConfig.Engine` | `sqlite` (default), `postgres` or `mysql`. The DSN comes from `OPENZRO_STORE_ENGINE_POSTGRES_DSN` or `OPENZRO_STORE_ENGINE_MYSQL_DSN`. See [SQLite](/selfhosted/sqlite-store) and [PostgreSQL](/selfhosted/postgres-store). |
| `Datadir` | Data directory. Empty means the `--datadir` flag (default `/var/lib/openzro/`). |
| `DataStoreEncryptionKey` | Key that encrypts sensitive fields in the database. Generated on first start if empty; keep it, or encrypted data becomes unreadable. |
| `WgPrivateKey` | The management server's WireGuard identity. Generated and saved on first start if empty. Several management replicas must share it. |
| `DisableDefaultPolicy` | Do not create the all-to-all `Default` policy for new accounts. |

### Reverse proxy and client IPs

| Field | Description |
|---|---|
| `ReverseProxy.TrustedHTTPProxies` | IP prefixes of HTTP proxies whose `X-Forwarded-For` the HTTP API trusts. |
| `ReverseProxy.TrustedHTTPProxiesCount` | Number of proxies in front of the server, as an alternative to listing them. |
| `ReverseProxy.TrustedPeers` | IP prefixes whose forwarded client IP the gRPC server trusts. |

<Warning>
    The template sets `TrustedPeers` to `0.0.0.0/0`, so the gRPC server takes a client's IP from forwarding headers
    sent by anyone. A client can then report a different IP, which affects the peer location and geolocation posture
    checks. An empty list means the same as `0.0.0.0/0` (the server logs a warning at startup). If peers connect
    directly, set it to a prefix no client uses, such as `127.0.0.1/32`; behind a proxy, set it to the proxy's
    addresses.
</Warning>

## dex.config.yaml

Mounted at `/etc/dex/config.yaml` in the `dex` container.

| Section | Description |
|---|---|
| `issuer` | `https://<your-domain>/dex`. Dex serves its routes under this path. |
| `storage` | Dex's own database, SQLite in `/var/lib/dex/dex.db` (the `openzro-dex` volume). |
| `grpc` | The gRPC API management uses to manage connectors, on port 5557 with mTLS (`grpc-certs/`). |
| `staticClients` | The `openzro-dashboard` client used by the dashboard and the CLI, with redirect URIs `/auth`, `/silent-auth`, `/peers` and `/`. |
| `staticPasswords` | The bootstrap admin account, from `OPENZRO_DEX_ADMIN_EMAIL` and `OPENZRO_DEX_ADMIN_PASSWORD_BCRYPT`. |
| `connectors` | Upstream identity providers. Usually managed from **Settings → Auth Providers** in the dashboard instead. |

## turnserver.conf

Coturn's configuration. The values you are most likely to change come from `setup.env`:

| Setting | Source |
|---|---|
| `listening-port` 3478, `tls-listening-port` 5349 | fixed in the template |
| `min-port`, `max-port` (relay range, default 49152-65535) | `TURN_MIN_PORT`, `TURN_MAX_PORT` |
| `external-ip` | `OPENZRO_TURN_EXTERNAL_IP`, or discovered by `configure.sh` |
| `user` | `TURN_USER` and the generated `TURN_PASSWORD` |
