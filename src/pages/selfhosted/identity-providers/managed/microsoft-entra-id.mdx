# Microsoft and Entra ID SSO with openZro Self-Hosted

Use Microsoft accounts for authentication with openZro. This supports both personal Microsoft accounts and Microsoft Entra ID (formerly Azure AD) for work and school accounts.

## Management Setup (Recommended)

Add Microsoft as an authentication provider of openZro's embedded Dex from the dashboard. Use the **Microsoft Entra
ID** provider type for both work/school accounts and personal Microsoft accounts; the **Tenant** field decides who can
sign in:

| Tenant | Who can sign in |
|--------|-----------------|
| Your Directory (tenant) ID | Accounts of your organization only (recommended) |
| `organizations` | Work or school accounts from any Entra ID tenant |
| `consumers` | Personal Microsoft accounts only |
| `common` | Work, school and personal accounts |

### Prerequisites

- An openZro self-hosted deployment with the embedded Dex (the default), and the dashboard's
  **Settings → Auth Providers** page working (management needs `OPENZRO_DEX_GRPC_ADDR`; the Docker Compose stack sets
  it)
- Access to the [Entra Admin Center](https://entra.microsoft.com/)

### Step 1: Register an Application in Entra ID

1. In the [Entra Admin Center](https://entra.microsoft.com/), go to **App registrations** → **New registration**.
2. Fill in:
   - **Name**: `openZro`
   - **Supported account types**: match the tenant you will use (single tenant for your organization only)
   - **Redirect URI**: platform **Web**, URI `https://<your-domain>/dex/callback`
3. Click **Register** and note the **Application (client) ID** and **Directory (tenant) ID**.

### Step 2: Create a Client Secret

1. Go to **Certificates & secrets** and click **New client secret**.
2. Add a description and expiration, then click **Add**.
3. Copy the **Value** immediately (it won't be shown again).

<p>
    <img src="/docs-static/img/selfhosted/identity-providers/managed/microsoft-entra-id/5_copy-secret-microsoft-entra.png" alt="Copy secret" className="imagewrapper-big"/>
</p>

### Step 3: Add Microsoft Entra ID in openZro

1. In the openZro dashboard, go to **Settings → Auth Providers** and click **Add provider**.
2. Fill in the form:

| Field | Value |
|-------|-------|
| ID | `entra` |
| Type | Microsoft Entra ID |
| Display name | `Microsoft` |
| Tenant | Your Directory (tenant) ID, or `organizations`, `consumers` or `common` |
| Client ID | The Application (client) ID from Step 1 |
| Client Secret | The Value from Step 2 |
| Redirect URI | Prefilled: `https://<your-domain>/dex/callback` |

3. Click **Add provider**.

<p>
    <img src="/docs-static/img/selfhosted/identity-providers/openzro-add-provider-microsoft.png" alt="Add authentication provider dialog" className="imagewrapper-big"/>
</p>

### Step 4: Test the Connection

1. Log out of the openZro dashboard.
2. The sign-in page now shows **Log in with Microsoft**.
3. Click it and sign in with your Microsoft account.
4. You are redirected back to openZro and logged in. A user who logs in for the first time is added to the account
   with the default role.

### Configuring JWT 'groups' Claim

To sync Entra ID groups with openZro, you need to configure your app registration to include group claims in the ID token.

#### Step 1: Configure Groups Claim in Azure

1. In [Entra Admin Center](https://entra.microsoft.com/), go to your app registration
2. Navigate to **Token configuration**
3. Click **Add groups claim**

<p>
    <img src="/docs-static/img/selfhosted/identity-providers/managed/microsoft-entra-id/jwt_add-groups-claim.png" alt="Add groups claim" className="imagewrapper-big"/>
</p>

4. Select the group types to include:
   - **Security groups** - Recommended for most use cases
   - **Groups assigned to the application** - Recommended for large organizations (avoids token size limits)
5. Under **Customize token properties by type**, expand **ID** and select:
   - **Group ID** - Returns Azure object IDs (default)
6. Click **Add**

<p>
    <img src="/docs-static/img/selfhosted/identity-providers/managed/microsoft-entra-id/jwt_configure-groups-claim.png" alt="Add groups claim" className="imagewrapper-big"/>
</p>

<Note>
**Token size limit:** Entra ID limits groups to 200 in JWT tokens. If a user belongs to more groups, the claim is omitted entirely. Use **Groups assigned to the application** to avoid this by only including relevant groups.
</Note>

#### Step 2: Assign Groups to the Application (Recommended)

If you selected "Groups assigned to the application":

1. Go to **Enterprise applications** in Entra Admin Center
2. Find and select your openZro application
3. Go to **Users and groups**
4. Click **Add user/group**
5. Select the groups you want to sync with openZro
6. Click **Assign**

<Note>
Dex passes upstream groups on only when its connector sets `insecureEnableGroups: true` and requests the `groups`
scope. Connectors added from **Settings → Auth Providers** do not set these, so the claim does not reach openZro.
To use JWT group sync, declare the connector in `dex.config.yaml` instead (Docker Compose: `artifacts/dex.config.yaml`;
Helm: `dex.config.connectors`), as in the
[Helm quickstart](/selfhosted/kubernetes/helm-quickstart#jwt-group-sync-when-using-an-upstream-id-p).
</Note>

#### Step 3: Enable JWT Group Sync in openZro

1. In openZro Dashboard, go to **Settings** → **Groups**
2. Enable **JWT group sync**
3. Set **JWT claim** to `groups`
4. Optionally configure **JWT allow group** to restrict access

<Note>
Entra ID returns group **object IDs** (GUIDs) by default, not group names. Your openZro groups will appear as IDs like `a1b2c3d4-5678-90ab-cdef-1234567890ab`. To use display names instead, you need Azure AD Premium and cloud-only groups, or provision users and groups with [SCIM](/manage/team/idp-sync) instead of JWT group sync.
</Note>

## Standalone Setup (Advanced)

Point openZro's management server and dashboard directly at Microsoft Entra ID, without Dex in between. This gives you full
control over authentication but needs more setup, and some features (such as adding providers from the dashboard) do
not apply.

For detailed instructions on the standalone setup, see the [Microsoft and Entra ID SSO with openZro Self-Hosted (Legacy)](/selfhosted/identity-providers/managed/advanced/microsoft-entra-id) documentation.

<Note>
If you prefer to have full control over authentication, consider self-hosted alternatives like [PocketID](/selfhosted/identity-providers/pocketid).
</Note>

## Troubleshooting

### "AADSTS50011: The redirect URI specified in the request does not match"

- Ensure the redirect URI in Azure exactly matches what openZro provides
- Check platform type (SPA vs Mobile/Desktop)
- Verify no trailing slashes

### "AADSTS700016: Application not found"

- Verify the Application (client) ID is correct
- Check tenant ID for single-tenant apps
- Ensure the app registration is in the correct directory

### Users from wrong tenant signing in

- Use single-tenant configuration for organization-only access
- Verify "Supported account types" setting in app registration
