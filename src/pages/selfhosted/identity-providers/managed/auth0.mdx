# Auth0 SSO with openZro Self-Hosted

[Auth0](https://auth0.com/) is a flexible, drop-in solution to add authentication and authorization services to your applications. It's a managed service that handles identity infrastructure so you don't have to.

## Management Setup (Recommended)

Add Auth0 as an authentication provider of openZro's embedded Dex from the dashboard. This is the simplest approach and recommended for most deployments.

### Prerequisites

- An openZro self-hosted deployment with the embedded Dex (the default), and the dashboard's
  **Settings → Auth Providers** page working (management needs `OPENZRO_DEX_GRPC_ADDR`; the Docker Compose stack sets
  it)
- An Auth0 account (sign up at https://auth0.com/)

### Step 1: Create an Application in Auth0

1. Log in to your Auth0 dashboard at https://manage.auth0.com/ and go to **Applications** → **Applications**.
2. Click **Create Application**, name it `openZro`, choose **Regular Web Application**, and click **Create**.
3. On the **Settings** tab, under **Allowed Callback URLs**, add `https://<your-domain>/dex/callback` and click **Save Changes**.
4. Note the **Client ID**, **Client Secret** and **Domain** (e.g. `your-tenant.auth0.com`) shown on the same tab.

### Step 2: Add Auth0 in openZro

1. In the openZro dashboard, go to **Settings → Auth Providers** and click **Add provider**.
2. Fill in the form:

| Field | Value |
|-------|-------|
| ID | `auth0` |
| Type | Generic OIDC |
| Display name | `Auth0` |
| Issuer URL | `https://your-tenant.auth0.com/` **(with the trailing slash)** |
| Client ID | From Step 1 |
| Client Secret | From Step 1 |
| Redirect URI | Prefilled: `https://<your-domain>/dex/callback` |

3. Click **Add provider**.

<p>
    <img src="/docs-static/img/selfhosted/identity-providers/openzro-add-provider-oidc.png" alt="Add authentication provider dialog" className="imagewrapper-big"/>
</p>

### Step 3: Test the Connection

1. Log out of the openZro dashboard.
2. The sign-in page now shows **Log in with Auth0**.
3. Click it and authenticate with your Auth0 credentials.
4. You are redirected back to openZro and logged in. A user who logs in for the first time is added to the account
   with the default role.

## Standalone Setup (Advanced)

Point openZro's management server and dashboard directly at Auth0, without Dex in between. This gives you full
control over authentication but needs more setup, and some features (such as adding providers from the dashboard) do
not apply.

For detailed instructions on the standalone setup, see the [Auth0 SSO with openZro Self-Hosted (Legacy)](/selfhosted/identity-providers/managed/advanced/auth0) documentation.

<Note>
If you prefer to have full control over authentication, consider self-hosted alternatives like [PocketID](/selfhosted/identity-providers/pocketid).
</Note>

---

## Troubleshooting

### "Invalid redirect URI" error

- Ensure all callback URLs are configured in Auth0
- Check for trailing slashes
- Verify URLs match exactly
