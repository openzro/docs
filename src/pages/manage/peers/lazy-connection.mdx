# Lazy Connections
Lazy connections are an experimental feature that connects to peers only when they are needed. Instead of keeping a
connection open to every peer in the network map, the openZro client opens a connection when there is traffic or
signaling for that peer, and closes it again after a period of inactivity.

<Note>
    This feature is experimental. Functionality and behavior may change in future releases.
</Note>

## What are lazy connections?

When enabled, the openZro client:

- Establishes peer-to-peer connections **only when needed**, for example when you ping a remote peer.
- Monitors peer activity and **closes connections** that stay idle longer than the inactivity threshold.
- Keeps excluded peers **always connected**.

This is useful in **large deployments** or **resource-constrained devices**, where a permanent full mesh to every
peer is unnecessary.

<Note>
    The first packet to a peer that is not connected yet may see a **short delay** while the connection is
    established.
</Note>

### How automatic disconnection works

Once a connection is open, it stays open while there is WireGuard activity with the remote peer. If no activity is
seen for longer than the inactivity threshold, the connection goes idle, even if the remote peer is still reachable.
The next packet to that peer opens it again.

The default threshold is **15 minutes**. Change it with the `OZ_LAZY_CONN_INACTIVITY_THRESHOLD` environment
variable, set to a whole number of minutes (minimum 1):

```bash
export OZ_LAZY_CONN_INACTIVITY_THRESHOLD=30
```

## Enabling in the dashboard

Go to **Settings → Clients** and turn on **Enable lazy connections** in the **Experimental** card. The change is
saved immediately and reaches every client in the account on its next network map update.

- **Enabled:** the client starts its lazy connection manager. Existing connections stay open until they are idle
  for longer than the inactivity threshold.
- **Disabled:** the client stops the lazy connection manager and connects to all remote peers.

## Enabling on a single client

Lazy connections are disabled by default. To enable them on one client regardless of the account setting, use the
CLI flag. It is saved in the active profile and survives restarts:

```bash
openzro up --enable-lazy-connection
```

Or set the environment variable on the client service. It applies only to that process, so add it to your service
definition (systemd, Docker, etc.):

```bash
export OZ_ENABLE_EXPERIMENTAL_LAZY_CONN=true
```

You can also toggle it from the desktop app: open the openZro tray menu, go to **Settings** and click
**Enable Lazy Connections**.

<Note>
    When lazy connections are enabled locally, the account setting in the dashboard cannot turn them off on that
    client.
</Note>

## Limitations

- Lazy connections are not started when [quantum resistance (Rosenpass)](/client/post-quantum-cryptography)
  is enabled on the client.
- Remote peers must run openZro (or a NetBird-compatible client) v0.45.0 or later. Every openZro release meets this.
