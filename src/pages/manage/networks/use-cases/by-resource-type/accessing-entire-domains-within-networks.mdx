# Accessing entire domains within networks

This guide shows how to provide access to entire internal domains using openZro [Networks](/manage/networks) with [wildcard domain resources](/manage/networks#resources). Wildcard domains simplify access management when teams need to reach multiple subdomains under a common parent domain.

## Example scenario

An AI software company needs to provide secure access to two internal environments:

1. **Development environment** (`*.dev.example.com`): Shared workspace for code development, testing, and collaboration
2. **AI model training environment** (`*.ai.example.com`): Sensitive AI models and datasets with restricted access

Using wildcard domains, developers can access any subdomain under `*.dev.example.com`, while data scientists access `*.ai.example.com`. This separation ensures team members only reach resources relevant to their roles.

### Prerequisites

Before starting, ensure you have:
- [openZro clients](/get-started) installed on developer and data scientist devices
- [Routing peers](/manage/networks#routing-peers) in your network, added with [setup keys](/manage/peers/access-infrastructure/setup-keys-add-servers-to-network)
- A routing peer that can resolve the internal domains. If it cannot, add a [nameserver](/manage/dns) distributed to
  the routing peer's group.

## Enable DNS wildcard routing

DNS wildcard routing lets routing peers resolve domains on behalf of clients, which wildcard domain resources need.
It is **enabled by default** for new accounts. To check it, go to **Settings** > **Networks** and confirm that
**Enable DNS wildcard routing** is on:

![DNS wildcard routing setting](/docs-static/img/manage/networks/use-cases/by-resource-type/accessing-entire-domains-within-networks/01-domains-within-networks.png)

<Note>
Restart your routing peers and clients after changing this setting.
</Note>

## Set up the development network

### Create the network

1. Go to **Networks** and click **Add Network**.
2. Enter a name (e.g., `Development Network`) and an optional description.
3. Click **Add Network**.

### Add routing peers

Open the network, go to the **Routing Peers** tab and click **Add Routing Peer**. Select a single peer under
**Routing Peers**, or a **Peer Group** for high availability, click **Continue**, keep **Masquerade** on, and click
**Add Routing Peer**.

### Add a wildcard domain resource

On the **Resources** tab, click **Add Resource** and configure:

- **Name**: `Development Wildcard Domain`
- **Address**: `*.dev.example.com`
- **Destination Groups**: create or select `development-domain`

Click **Add Resource**.

### Create an access policy

Click **Add Policy** on the resource's row. The destination is already `development-domain`. Set:

- **Protocol**: `ALL`
- **Source**: `developers`

Click **Continue** to optionally add posture checks, then **Continue** again. Name the policy (e.g.,
`Development wildcard domain policy`) and click **Add Policy**.

### Add the base domain resource

To be sure `dev.example.com` itself is reachable, add it as a separate resource. Click **Add Resource** again:

- **Name**: `Development Regular Domain`
- **Address**: `dev.example.com`
- **Destination Groups**: `development-domain`, the same group as the wildcard

Because it shares the group, the existing routing peers and policy apply to it automatically:

![Development Network resources](/docs-static/img/manage/networks/use-cases/by-resource-type/accessing-entire-domains-within-networks/13-domains-within-networks.png)

Verify the configuration from a developer workstation:

```bash
$ openzro networks ls
Available Networks:

  - ID: Development Regular Domain
    Domains: dev.example.com
    Status: Selected
    Resolved IPs:
      [dev.example.com]: 93.184.215.14

  - ID: Development Wildcard Domain
    Domains: *.dev.example.com
    Status: Selected
    Resolved IPs: -
```

## Set up the AI model training network

Follow the same steps to create a network for data scientists:

1. Create a network named `AI Model Training Network` and add its routing peers.
2. Add the wildcard resource `*.ai.example.com` in a new `ai-domain` group.
3. Click **Add Policy** on it and grant the `data-scientists` group access with protocol `ALL`.
4. Add the base domain `ai.example.com` as another resource in `ai-domain`.

### Add specific subdomain resources

You can also add individual subdomains as resources, for example to give them their own policies later. Click
**Add Resource**, enter the subdomain (e.g., `quantumnet.ai.example.com`) and assign it to a group. Here all of them
use `ai-domain`:

![AI Model Training Network resources](/docs-static/img/manage/networks/use-cases/by-resource-type/accessing-entire-domains-within-networks/20-domains-within-networks.png)

Verify from a data scientist workstation:

```bash
$ openzro networks ls
Available Networks:

  - ID: AI Model Training Wildcard Domain
    Domains: *.ai.example.com
    Status: Selected
    Resolved IPs: -

  - ID: AI Regular Domain
    Domains: ai.example.com
    Status: Selected
    Resolved IPs: -

  - ID: DataSage Model
    Domains: datasage.ai.example.com
    Status: Selected
    Resolved IPs: -

  - ID: NeuroPulse Model
    Domains: neuropulse.ai.example.com
    Status: Selected
    Resolved IPs: -

  - ID: QuantumNet Model
    Domains: quantumnet.ai.example.com
    Status: Selected
    Resolved IPs: -
```

Data scientists now have access to `ai.example.com` and all its subdomains. You can create additional access policies for individual subdomains or organize data scientists into teams with different permissions as needed.
