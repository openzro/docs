# Routing traffic to multiple IP resources

This guide shows how to route traffic to multiple IP resources using openZro [Networks](/manage/networks) with [IP resources](/manage/networks#resources). This is a common scenario for DevOps and Platform teams who need to provide differentiated access to on-premises or cloud infrastructure.

## Example scenario

In this example, you will configure access to an internal network (`172.16.0.0/15`) with these requirements:
- All users need access to DNS servers at `172.16.30.2` and `172.17.100.2` (UDP port 53 only)
- The DevOps team needs full access to the entire network range

Traffic will be routed through [routing peers](/manage/networks#routing-peers) running inside the network.

### Create a network

Go to **Networks** and click **Add Network**. Enter a name, for example `Office network`, and an optional
description, then click **Add Network**. The dashboard offers to add a resource next; you can follow the prompts or
use the network page as described below.

### Add a routing peer

Open the network, go to the **Routing Peers** tab and click **Add Routing Peer**. Select a peer inside the office
network, or a **Peer Group** with several of them for high availability, click **Continue**, keep the defaults and
click **Add Routing Peer**.

### Add the network resource

On the **Resources** tab, click **Add Resource** and fill in:

1. **Name**: `Office network`
2. **Address**: `172.16.0.0/15`
3. **Destination Groups**: `office-network`. The DevOps policy will use this group.

Click **Add Resource**.

### Add the DNS server resources

Add two more resources the same way, both in the `office-dns-servers` group:

- `DNS 1` with address `172.16.30.2`
- `DNS 2` with address `172.17.100.2`

Because both share one group, a single policy covers them.

### Create the access policies

Click **Add Policy** on the `Office network` row. The destination is already set to `office-network`. Set:

- **Source**: `devops`
- **Protocol**: `ALL`

Click **Continue**, name the policy (for example `DevOps to office network`), and click **Add Policy**.

Then click **Add Policy** on one of the DNS rows and set:

- **Source**: `All`
- **Protocol**: `UDP`, **Ports**: `53`

Name it `All users to office DNS` and save it. Policies to resources are one-way: peers can reach the resources, but
the resources cannot open connections back to the peers.

### View the network

The network page now lists the three resources with their groups and policies:

<p>
    <img src="/docs-static/img/manage/networks/use-cases/by-resource-type/routing-traffic-to-multiple-resources/view-example-network-2.png" alt="Office network with three resources" className="imagewrapper-big"/>
</p>

To change a resource or routing peer later, use the **⋮** menu on its row.

You have now created a network with multiple resources that provide different access levels to different user groups within your organization.
