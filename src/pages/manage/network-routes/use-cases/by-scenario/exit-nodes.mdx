# Configuring Exit Nodes for Internet Traffic

Exit nodes route all internet-bound traffic from your devices through a designated routing peer. This guide explains how to configure default routes for internet traffic.

## Concepts

### Default Routes

A default route (`0.0.0.0/0` for IPv4) directs all internet traffic through a designated routing peer.

<Note>
    IPv6 traffic is currently not supported and is blocked to prevent unintentional leakage.
</Note>

### Routing Peer

The routing peer acts as the exit node for internet traffic. Masquerading is always on for exit nodes, so traffic appears to originate from the routing peer's public IP address.

### Distribution Groups

Peers in the distribution groups send their internet traffic through the routing peer once it connects.

<Note>
    Like any network route, an exit node is only used by peers that can connect to the routing peer: an enabled
    access control policy must connect the distribution groups to a group that contains the routing peer. Any
    protocol works, for example ICMP.
</Note>

### Exit Node Selection on the Client

Exit nodes are applied automatically to every peer in the distribution groups. A user can opt out on their own device:

- in the tray, open **Exit Node** and choose another exit node or **Deselect All**;
- or run `openzro networks deselect <route-id>` (see `openzro networks list` for the ID).

That choice is kept on the device.

## Configuration Steps

### 1. Start from the routing peer

In the openZro dashboard, go to **Peers**, open the row menu (**⋮**) of the peer that will be the exit node and choose
**Set Up Exit Node** (or **Add Exit Node** if the peer already has one). You can also click **Add Exit Node** on the
**Network Routes** page and pick the routing peer or peer group there.

<p>
    <img src="/docs-static/img/manage/network-routes/use-cases/by-scenario/exit-nodes/openzro-peers.png" alt="Set Up Exit Node in the peer's row menu" className="imagewrapper-big"/>
</p>

### 2. Configure the exit node

In the **Add Exit Node** dialog:

1. **Groups**: choose the **Distribution Groups** whose peers should send their internet traffic through this exit
   node. **Access Control Groups** are optional. Click **Continue**.
2. **Name & Description**: the identifier is pre-filled as `Exit Node (<peer>)`. Click **Continue**.
3. **Additional Settings**: keep **Enable Route** on and adjust the **Metric** if you run several exit nodes.
4. Click **Add Exit Node**.

<p>
    <img src="/docs-static/img/manage/network-routes/use-cases/by-scenario/exit-nodes/openzro-peers-add-exit-node.png" alt="Add Exit Node dialog" className="imagewrapper"/>
</p>

### 3. Verify the configuration

The exit node appears on the **Network Routes** page:

<p>
    <img src="/docs-static/img/manage/network-routes/use-cases/by-scenario/exit-nodes/openzro-peers-routing-peer-exit-node.png" alt="Exit node in the Network Routes list" className="imagewrapper-big"/>
</p>

### 4. Configure DNS

Add a nameserver with **Match Domains** left empty, so it resolves all domains, and distribute it to the same groups.
Local DNS servers may not be reachable from the exit node, and this also prevents DNS-based location leaks.

See [Manage DNS in your network](/manage/dns) for details.

## High Availability
