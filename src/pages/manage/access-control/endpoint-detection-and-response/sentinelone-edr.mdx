# Restrict Network Access with SentinelOne Singularity™

[SentinelOne Singularity](https://www.sentinelone.com/platform/) is an endpoint protection platform. The SentinelOne
agent runs on your devices and reports their state to the SentinelOne console, which openZro can use to limit network
access to devices with active, healthy protection.

## What openZro checks

openZro looks up the peer's hostname (the agent's computer name) in SentinelOne. These conditions always apply; a
device fails if:

- no agent is registered for that hostname;
- the agent is decommissioned;
- the agent reports the device as infected;
- the agent is not active.

You can add these optional conditions when you add the provider:

| Option | Fails the device when |
|---|---|
| **Max active threats (optional)** | the number of active threats is above this value. Blank means no threshold. |
| **Require disk encryption** | disk encryption is not reported as enabled. |
| **Require host firewall** | the host firewall is not enabled. |
| **Require console connectivity** | the agent's network status is not `connected`. |
| **Minimum agent version (optional)** | the agent version is older than this, or cannot be parsed. Blank means no floor. |
| **Sync window in minutes (optional)** | the agent last checked in longer ago than this, or its last check-in is unknown. Blank means no recency requirement. |

## Prerequisites

- A SentinelOne account with permission to create service users. If you don't have it, ask your SentinelOne
  administrator.

## Create a SentinelOne API token

1. In the SentinelOne Management Console, go to **Settings → Users → Service Users**.
2. Click **Create Service User** and fill in the form:
   - **Name**: `openZro Integration`;
   - **Expiration Date**: your preferred expiration date.
3. Click **Next**, select the site and set the scope to **Viewer**.
4. Click **Create User** and copy the API token. It is shown only once.
5. Note your console URL from the browser's address bar, for example `https://your-tenant.sentinelone.net`.

## Add SentinelOne to openZro

1. In the openZro dashboard, go to **Integrations → MDM / EDR** and click **Add provider**.
2. Fill in the **Add MDM/EDR provider** dialog:
   - **Name**: a label for this provider, for example `sentinelone-prod`.
   - **Type**: SentinelOne.
   - **Refresh interval (minutes)**: how long a device's status is cached (1–60, default 5).
   - **Management URL**: your console URL.
   - **API Token**: the token from the previous step.
   - The optional conditions from [What openZro checks](#what-open-zro-checks).
3. Click **Create**.

## Enforce the check

1. Go to **Posture Checks**, create a check and add **Endpoint Security (MDM/EDR)** with the SentinelOne provider.
2. Use the check in one or both ways:
   - attach it to [access control policies](/manage/access-control/manage-network-access): failing peers are removed
     from those policies' sources;
   - add it to [Device Admission](/manage/access-control/posture-checks/device-admission) and enforce it: failing
     devices are refused at login and sync, and connected ones are disconnected.

See the [MDM / EDR overview](/manage/access-control/endpoint-detection-and-response) for how the two compare.

## Notes

- Devices are matched by hostname. Make sure each peer's hostname matches the computer name SentinelOne reports, and
  that hostnames are unique.
- A device's status is refreshed after the provider's refresh interval, so changes in SentinelOne take a few minutes
  to reach openZro.
- If the SentinelOne API cannot be reached, the check fails closed unless **Fail open on lookup error** is enabled on
  the posture check.
- To let a single non-compliant device in temporarily, use an
  [admission bypass](/manage/access-control/endpoint-detection-and-response/bypass-compliance).
