# Restrict Network Access with Huntress EDR

[Huntress](https://www.huntress.com/) is a managed detection and response (MDR) platform for IT service providers
and enterprises. The Huntress agent monitors endpoints and reports to the Huntress console, which openZro can use to
limit network access to devices with a healthy agent and no open incidents.

## What openZro checks

openZro looks up the peer's hostname in the Huntress API and treats the device as compliant only when:

- a Huntress agent is registered for that hostname;
- the device has no open incident reports;
- the agent is not flagged as outdated.

There are no tunable criteria for Huntress.

## Prerequisites

- A Huntress account with permission to create API credentials. If you don't have it, ask your Huntress
  administrator.

## Create Huntress API credentials

1. In the Huntress dashboard, go to **Account Settings → API Credentials** and click **Create API Credential**.
2. Name it, for example `openZro Integration`, and click **Create**.
3. Copy the **API key** and **API secret**. They are shown only once.

## Add Huntress to openZro

1. In the openZro dashboard, go to **Integrations → MDM / EDR** and click **Add provider**.
2. Fill in the **Add MDM/EDR provider** dialog:
   - **Name**: a label for this provider, for example `huntress-prod`.
   - **Type**: Huntress.
   - **Refresh interval (minutes)**: how long a device's status is cached (1–60, default 5).
   - **API Key** and **API Secret**: the credentials from the previous step.
3. Click **Create**.

## Enforce the check

1. Go to **Posture Checks**, create a check and add **Endpoint Security (MDM/EDR)** with the Huntress provider.
2. Use the check in one or both ways:
   - attach it to [access control policies](/manage/access-control/manage-network-access): failing peers are removed
     from those policies' sources;
   - add it to [Device Admission](/manage/access-control/posture-checks/device-admission) and enforce it: failing
     devices are refused at login and sync, and connected ones are disconnected.

See the [MDM / EDR overview](/manage/access-control/endpoint-detection-and-response) for how the two compare.

## Notes

- Devices are matched by hostname. Make sure each peer's hostname matches the hostname the Huntress agent reports,
  and that hostnames are unique.
- A device's status is refreshed after the provider's refresh interval, so changes in Huntress take a few minutes to
  reach openZro.
- If the Huntress API cannot be reached, the check fails closed unless **Fail open on lookup error** is enabled on the
  posture check.
- To let a single non-compliant device in temporarily, use an
  [admission bypass](/manage/access-control/endpoint-detection-and-response/bypass-compliance).
