# Restrict Network Access with CrowdStrike Falcon®

[CrowdStrike Falcon](https://www.crowdstrike.com/platform/) is a cloud-based endpoint protection platform. The Falcon
sensor runs on your devices and reports their state to the Falcon cloud, which openZro can use to limit network access
to IT-managed devices whose sensor is healthy.

## What openZro checks

openZro looks up the peer's hostname in Falcon and treats the device as compliant only when:

- a Falcon sensor is registered for that hostname;
- the host status is `normal`. A host that is `contained`, `containment_pending` or `lift_containment_pending` fails,
  so containing a host in Falcon also cuts its openZro access;
- the sensor is not in reduced functionality mode.

## Prerequisites

- A CrowdStrike account with permission to create API clients. If you don't have it, ask your CrowdStrike
  administrator.
- The Falcon cloud region of your tenant (US-1, US-2, EU-1, US-GOV-1 or US-GOV-2). An API client only works in its
  home region.

## Create a CrowdStrike API client

1. In your Falcon console, go to **Support → API Clients and Keys**.
2. Click **Create API client**.
3. Give it a name, for example `openZro`, and grant only the **Hosts: Read** scope.
4. Click **Create** and copy the **Client ID** and **Secret**. The secret is shown only once.

## Add CrowdStrike to openZro

1. In the openZro dashboard, go to **Integrations → MDM / EDR** and click **Add provider**.
2. Fill in the **Add MDM/EDR provider** dialog:
   - **Name**: a label for this provider, for example `crowdstrike-prod`.
   - **Type**: CrowdStrike Falcon.
   - **Refresh interval (minutes)**: how long a device's status is cached (1–60, default 5).
   - **Cloud**: your Falcon region. A mismatch returns an authentication error.
   - **API Client ID** and **API Client Secret**: the credentials from the previous step.
3. Click **Create**.

## Enforce the check

1. Go to **Posture Checks**, create a check and add **Endpoint Security (MDM/EDR)** with the CrowdStrike provider.
2. Use the check in one or both ways:
   - attach it to [access control policies](/manage/access-control/manage-network-access): failing peers are removed
     from those policies' sources;
   - add it to [Device Admission](/manage/access-control/posture-checks/device-admission) and enforce it: failing
     devices are refused at login and sync, and connected ones are disconnected.

See the [MDM / EDR overview](/manage/access-control/endpoint-detection-and-response) for how the two compare.

## Verify the integration

To see the integration work, hide a test host in Falcon:

1. Go to [Host management](https://falcon.crowdstrike.com/host-management/hosts) in the Falcon console.
2. Select the host, click **Actions** and then **Hide**. The host moves to the trash.
3. Once the cached status expires (the refresh interval) and the next revalidation runs, the peer fails the check.
   With Device Admission enforced, it is disconnected and a **Peer admission denied** event appears in the activity
   log.
4. Restore the host from the trash. Access returns after the next refresh.

## Notes

- Devices are matched by hostname. Make sure each peer's hostname matches the hostname Falcon reports, and that
  hostnames are unique.
- If the Falcon API cannot be reached, the check fails closed unless **Fail open on lookup error** is enabled on the
  posture check.
- To let a single non-compliant device in temporarily, use an
  [admission bypass](/manage/access-control/endpoint-detection-and-response/bypass-compliance).
