# Enforce periodic user authentication

To ensure a high level of security, openZro can require users to periodically re-authenticate the devices they added
with SSO. New accounts have this enabled with a 24-hour period. You can change or disable it in
**Settings** → **Authentication**, under **Peer session expiration**.

<Note>
    This only applies to peers added with the [interactive SSO login](/get-started/install#running-open-zro-with-sso-login).
    Peers added with a setup key have no user to sign in and are not affected.
</Note>

Expired peers appear in the **Peers** list with the notice `Login required` until the user signs in again.

## Configure and disable expiration

In **Settings** → **Authentication** → **Peer session expiration**:

- **Peer session expiration** turns the feature on or off for the whole account.
- **Session expiration** sets the period, in hours or days, between 1 hour and 180 days.
- **Require login after disconnect** additionally requires re-authentication when a peer has been disconnected from
  the management server for more than 10 minutes. It is off by default and only available while peer session
  expiration is on.

Click **Save Changes** to apply.

<Note>
    Enabling peer expiration or changing the expiration period will cause some peers added with the SSO login to
    disconnect, and re-authentication will be required.
</Note>

## Disable expiration individually per peer

Sometimes, you might want to disable expiration for some peers without disabling it globally. Open the peer from the
**Peers** list and use the **Session Expiration** card, or choose **Disable Session Expiration** in the peer's row
menu (**⋮**). The card also has a per-peer **Require login after disconnect** switch. Peers with expiration disabled are
marked `Expiration disabled` in the **Peers** list.
