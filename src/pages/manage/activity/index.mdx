# Audit Events Logging

openZro records an audit event for every change made through the management server: peers and users joining, policy
and group changes, settings updates, logins and more. Use the log to see who changed what and when.

## View audit events
Audit events are always on. In the dashboard, go to **Identity → Activity**. Use the search bar to search events, and
filter by date range, event type and the user who made the change.

<p>
    <img src="/docs-static/img/manage/activity/activity-monitoring.png" alt="Activity page" className="imagewrapper-big"/>
</p>

Each event shows a human-readable description and a stable code (on the right). The code is what streamed events and the API carry, so use it
when you filter events in a SIEM.

<Note>
    The `unknown` name or `unknown@unknown.com` email address may be displayed in the activity log if the encryption key
    has been corrupted or lost. The events returned by the API then show `unknown@unknown.com` for the email address
    and `unknown` for the name. The key is the <b>DataStoreEncryptionKey</b> field in <b>management.json</b>; restore
    it from your backup.
</Note>

## Stream audit events to a SIEM

openZro can send audit events to an HTTP endpoint, Datadog or Elasticsearch as they happen. See
[Event streaming](/manage/activity/event-streaming).

Network traffic between peers is recorded separately; see [Traffic events](/manage/activity/traffic-events-logging).
