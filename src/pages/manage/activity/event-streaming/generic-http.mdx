# Stream Activity Events to an HTTP Endpoint

The HTTP webhook exporter sends each openZro [audit event](/manage/activity) to an HTTP or HTTPS endpoint of your
choice: a custom SIEM, Splunk HEC, Grafana Loki, Vector, Fluent Bit, or any service that accepts `POST` requests.

## How events are sent

- One `POST` request per event, sent as soon as the event is recorded.
- The default body is JSON with `Content-Type: application/json`. You can replace it with a
  [custom payload template](/manage/activity/event-streaming/payload-templates).
- Server errors (5xx) and network errors are retried with exponential backoff, 3 attempts in total by default.
  Client errors (4xx) are not retried.
- The endpoint can be on a private network. The management server's own loopback address and cloud metadata
  endpoints are refused.

## Add the exporter in openZro

1. In the openZro dashboard, go to **System → Integrations** and open the **Activity Streamer** tab.
2. Click **Add exporter**.
3. Fill in the dialog:
   - **Name**: a label, for example `SIEM webhook`.
   - **Type**: **HTTP webhook**.
   - **URL**: the endpoint, for example `https://siem.example.com/webhooks/audit`.
   - **Headers (JSON)** (optional): extra request headers as a JSON object. Use them for authentication, for example
     `{"Authorization": "Bearer <token>"}`.
   - **Custom payload template** (optional): see [Custom payload templates](/manage/activity/event-streaming/payload-templates).
     Click **Validate template** to check it before saving.
4. Click **Create exporter**.

## Default payload

Without a template, each request body looks like this:

```json
{
  "id": 4127,
  "timestamp": "2026-10-22T21:12:15.402183Z",
  "activity": "personal.access.token.create",
  "activity_code": 41,
  "initiator_id": "c2e1d6f0-7f3a-4b0e-9d6c-1f0a2b3c4d5e",
  "initiator_name": "Alice",
  "initiator_email": "alice@example.com",
  "target_id": "9b990297-dabd-4976-9586-1cd8f9c4c2df",
  "account_id": "d1e4f6g8h0j2k4l6m8n0",
  "meta": {
    "is_service_user": true,
    "name": "terraform-ci",
    "user_name": "terraform"
  }
}
```

- `activity` is the event's code from the [audit event list](/manage/activity); `activity_code` is its numeric ID.
- `meta` depends on the event type.
- Fields without a value are left out.

## Configure with environment variables

To stream the events of every account, set these on the management server instead:

| Variable | Description |
|---|---|
| `OPENZRO_ACTIVITY_EXPORT_URL` | Endpoint URL. Enables the exporter. |
| `OPENZRO_ACTIVITY_EXPORT_HEADERS` | Extra headers as a JSON object, e.g. `{"Authorization":"Bearer <token>"}`. |
| `OPENZRO_ACTIVITY_EXPORT_TIMEOUT` | Timeout per attempt (default `5s`). |
| `OPENZRO_ACTIVITY_EXPORT_MAX_ATTEMPTS` | Attempts per event (default `3`). |
| `OPENZRO_ACTIVITY_EXPORT_INITIAL_BACKOFF` | Delay before the first retry, doubled after each attempt (default `200ms`). |
| `OPENZRO_ACTIVITY_EXPORT_TEMPLATE` | Custom payload template, inline or as `@/path/to/file`. |

<Note>
    This page covers audit events. To send network traffic events to an HTTP endpoint, use a

</Note>
