# Add users to your network

Users join an openZro account in three ways: by signing in through an identity provider, as local users created in
the dashboard, or provisioned over SCIM. Every user lands in the same account: self-hosted openZro runs in single-account
mode by default.

## Sign in through an identity provider

The usual way to add people is to let them sign in. Connect your identity provider to openZro's bundled Dex under
**Settings → Auth Providers** (see [Identity providers](/selfhosted/identity-providers)). A user who signs in for the
first time is added to the account with the **User** role.

- To restrict who can sign in, limit access to the openZro application at your identity provider, or use a **JWT allow
  group** (see [JWT group sync](/how-to/jwt-groups)).
- To bring groups from the identity provider, use [JWT group sync](/how-to/jwt-groups).

## Create local users

Local users sign in with an email and password stored in openZro's bundled Dex, without an external identity provider.
Under **Identity → Users & Groups → Users**, click **Create local user**, enter the email, an optional name, a password
and, optionally, groups to assign. The user can sign in right away.

The button appears only when local user creation is enabled on the management service
(`OPENZRO_SCIM_LOCAL_USERS_ENABLED=true`) and Dex is configured. See
[Provision local users via SCIM](/manage/team/idp-sync/scim-local-users) for the requirements; in particular, Dex must
use Postgres storage. We recommend turning on **Require 2FA for local accounts** under **Settings → Authentication**.

## Provision users over SCIM

An identity governance tool or identity provider can create and manage users and groups through openZro's SCIM 2.0
endpoint. See [Provision Users and Groups From Your Identity Provider](/manage/team/idp-sync).

## Manage user roles
openZro has five user roles - `Owner`, `Admin`, `Network Admin`, `Auditor` and `User`. The roles allow you to control the level of access to the management API of your account. 

- `Owner` role - has full access to the account and can manage all aspects of the account. There can be only one account owner in openZro. Users with the owner role can delete their organization account. See the [Delete openZro account](/manage/settings/delete-account) section for more.
- `Admin` role - has full access to the account except that administrators can't delete or update the role of the Owner user and delete the organization account.
- `Network Admin` role - has access to manage network configurations, including access policies, DNS settings, networks, and network routes, but they can only view user and device information and general settings.
- `Auditor` role - can read all configurations but not modify any of them.
- `User` role - has limited access to the account, allowing users to view peers they own and others they can connect to. Users can create personal access tokens for programmatic access.

|  | Owner | Admin | Network Admin | User | Auditor |
| --: | :--: | :--: | :--: | :--: | :--: |
| Peers | ✅ | ✅ | 📖 | 📖 | 📖 |
| Setup Keys | ✅ | ✅ | 📖 | ❌ | 📖 |
| Access Control | ✅ | ✅ | ✅ | ❌ | 📖 |
| Networks | ✅ | ✅ | ✅ | ❌ | 📖 |
| Network Routes | ✅ | ✅ | ✅ | ❌ | 📖 |
| DNS | ✅ | ✅ | ✅ | ❌ | 📖 |
| Team | ✅ | ✅ | 📖 | ❌ | 📖 |
| Activity | ✅ | ✅ | 📖 | ❌ | 📖 |
| Settings | ✅ | ✅ | 📖 | ❌ | 📖 |

| |
|-:|
|✅ = Full access \| 📖 = Read only \| ❌ = No access|


To change a user's role, go to **Identity → Users & Groups → Users**, click the user, select the role from the dropdown
and click **Save**.
<Note>
    Only users with the `Owner` role can assign another user as `Owner`; this action will transfer the `Owner` role to another user, making the current user `Admin`.
</Note>
