# Client Environment Variables

The openZro client reads a set of environment variables for advanced tuning and troubleshooting. They are separate
from the variables that mirror CLI flags (such as `OZ_LOG_LEVEL` or `OZ_MANAGEMENT_URL`), which are described in the
[CLI reference](/get-started/cli#environment-variables).

Most of these variables use the `OZ_` prefix. A few that belong to optional subsystems use `OPENZRO_`.

## Setting environment variables

Environment variables must be set on the **daemon process**, not the CLI. When running openZro as a system service,
use `--service-env` to persist them:

```shell
# Set during install
sudo openzro service install --service-env OZ_WG_KERNEL_DISABLED=true

# Or reconfigure an installed service
sudo openzro service reconfigure --service-env OZ_WG_KERNEL_DISABLED=true

# Multiple variables
sudo openzro service install --service-env OZ_LOG_FORMAT=json,OZ_USE_LEGACY_ROUTING=true
```

When running in foreground mode, set them in the shell before starting:
```shell
OZ_WG_KERNEL_DISABLED=true openzro up --foreground-mode
```

## Networking and routing

| Variable | Platform | Description |
|---|---|---|
| `OZ_USE_LEGACY_ROUTING` | Linux | Bypass the fwmark/ip-rule based routing and fall back to the simpler legacy routing method. Useful when exit nodes cause connectivity issues due to rp_filter or missing sysctl settings. |
| `OZ_SKIP_SOCKET_MARK` | Linux | Backward-compatibility alias for `OZ_USE_LEGACY_ROUTING`. |
| `OZ_DISABLE_CUSTOM_ROUTING` | All | Revert to the routing behavior from before exit node support was added. No exclusion routes or fwmark-based socket routing are used; all dialers and listeners fall back to plain `net.Dial`/`net.Listen`. Routes with a prefix of /7 or larger (e.g. default routes, 0.0.0.0/0) are rejected. |
| `OZ_DISABLE_ROUTE_CACHE` | Windows | Set to `true` to disable the cache on Windows routing table lookups, so every route change reads the routing table again. Only needed for debugging route conflicts. |

## WireGuard and interface

| Variable | Platform | Description |
|---|---|---|
| `OZ_WG_KERNEL_DISABLED` | Linux | Set to `true` to skip the WireGuard kernel module and run entirely in userspace (wireguard-go). Use this when the kernel module is broken, missing, or conflicts with other software. |
| `OZ_WG_DEBUG` | All | Set to `true` to print low-level WireGuard protocol messages (handshakes, keypairs, timers) to the log. Very verbose. |
| `OZ_USE_NETSTACK_MODE` | All | Set to `true` to run WireGuard on top of a userspace TCP/IP stack (gVisor netstack) instead of a TUN device. Required for environments without TUN support, such as unprivileged containers. |
| `OZ_NETSTACK_SKIP_PROXY` | All | In netstack mode, do not start the built-in SOCKS5 proxy that exposes the openZro network to local applications. |
| `OZ_SOCKS5_LISTENER_PORT` | All | Port of the netstack SOCKS5 proxy (default: `1080`). Only relevant in netstack mode. |

## Firewall

| Variable | Platform | Description |
|---|---|---|
| `OZ_SKIP_NFTABLES_CHECK` | Linux | Set to `true` to skip nftables and go straight to the iptables backend. Useful on systems where nftables is installed but not functional (e.g. missing kernel modules). |
| `OZ_DISABLE_CONNTRACK` | All | Turn off the stateful connection tracker in the userspace packet filter. With conntrack enabled (default), return traffic is allowed automatically; without it, the filter applies the explicit inbound rules from management instead. |
| `OZ_CONNTRACK_TCP_MAX` | All | Maximum number of TCP entries in the userspace connection tracker (default: `65536` on desktop and server, `4096` on mobile). When the table is full, the stalest entries are evicted. |
| `OZ_CONNTRACK_UDP_MAX` | All | Maximum number of UDP entries in the userspace connection tracker (default: `16384` on desktop and server, `2048` on mobile). |
| `OZ_CONNTRACK_ICMP_MAX` | All | Maximum number of ICMP entries in the userspace connection tracker (default: `2048` on desktop and server, `512` on mobile). |
| `OZ_DISABLE_USERSPACE_ROUTING` | All | Prevent the userspace packet filter from forwarding packets between interfaces. Routing rules from the management server are ignored when this is set. |
| `OZ_FORCE_USERSPACE_ROUTER` | All | Forward routed packets through the userspace router even when a native firewall backend (nftables/iptables) is available. The native backend still handles ACL rules. On macOS, Windows and in netstack mode the userspace router is always used. |
| `OZ_ENABLE_LOCAL_FORWARDING` | All | Allow the userspace filter to forward packets destined for local addresses (not just routed subnets). Off by default to prevent unexpected exposure of local services. |
| `OZ_ENABLE_NETSTACK_LOCAL_FORWARDING` | All | Same as `OZ_ENABLE_LOCAL_FORWARDING`, but only in netstack mode. Takes precedence over the general setting when both are set. |

## ICE and connectivity

| Variable | Platform | Description |
|---|---|---|
| `OZ_FORCE_RELAY` | All | Set to `true` to skip direct connectivity entirely: the client does not attempt ICE, and all peer traffic goes through the openZro Relay. Useful in egress-only environments. |
| `OZ_ICE_FORCE_RELAY_CONN` | All | Set to `true` to make ICE gather only TURN relay candidates, so connections established through ICE always go through the TURN server (Coturn). Mainly for testing. |
| `OZ_ICE_KEEP_ALIVE_INTERVAL_SEC` | All | How often, in seconds, ICE sends keepalive packets to maintain NAT bindings and detect connection liveness (default: `4`). |
| `OZ_ICE_DISCONNECTED_TIMEOUT_SEC` | All | Seconds of silence before ICE marks a connection as disconnected (default: `6`). |
| `OZ_ICE_FAILED_TIMEOUT_SEC` | All | Seconds of silence before ICE gives up on the connection (default: `6`). |
| `OZ_ICE_RELAY_ACCEPTANCE_MIN_WAIT_SEC` | All | Minimum seconds ICE waits for a direct candidate pair before accepting a TURN relay pair (default: `2`). |
| `OZ_ENABLE_EXPERIMENTAL_LAZY_CONN` | All | Set to `true` to open tunnels to peers only when traffic is detected, instead of connecting to all peers at startup. Same effect as the `--enable-lazy-connection` CLI flag. |
| `OZ_LAZY_CONN_INACTIVITY_THRESHOLD` | All | How long a lazy connection can be idle before it is torn down (Go duration, default: `15m`, minimum `1m`). Only applies when lazy connections are enabled. |

## Connection retry

These control the exponential backoff the daemon uses when it cannot connect to the management or signal server.

| Variable | Platform | Description |
|---|---|---|
| `OZ_CONN_RETRY_INTERVAL_TIME` | All | Initial backoff interval (Go duration, default: `30m`). The backoff is fully randomized, so actual waits range from almost zero to twice the current interval. |
| `OZ_CONN_MAX_RETRY_INTERVAL_TIME` | All | Upper bound on the backoff interval (Go duration, default: `60m`). |
| `OZ_CONN_MAX_RETRY_TIME_TIME` | All | Total time the daemon keeps retrying before giving up (Go duration, default: `336h`, i.e. 14 days). The double `_TIME` suffix is part of the variable name. |
| `OZ_CONN_RETRY_MULTIPLIER` | All | Factor by which the interval grows after each attempt (float, default: `1.7`). |

## Logging

| Variable | Platform | Description |
|---|---|---|
| `OZ_LOG_FORMAT` | All | Log line format: `json`, `syslog`, or the default text format. Logging to syslog always uses the `syslog` format. |
| `OZ_LOG_MAX_SIZE_MB` | All | Size in MB at which the log file is rotated (default: `15`). |

## DNS

| Variable | Platform | Description |
|---|---|---|
| `OZ_UNCLEAN_SHUTDOWN_RESOLV_FILE` | Linux, FreeBSD | Path where the client keeps a backup of `/etc/resolv.conf` before modifying it, so the original can be restored on the next start after a crash. |

## State and storage

| Variable | Platform | Description |
|---|---|---|
| `OZ_STATE_DIR` | All | Directory where the client keeps its profiles and state files. Defaults to `/var/lib/openzro` on Linux and macOS, `/var/db/openzro` on FreeBSD, and `%ProgramData%\Openzro` on Windows. |
| `OZ_DNS_STATE_FILE` | All | Path to the client state file (`state.json`). Despite the name, it is not DNS-specific: it holds all shutdown and recovery state, including DNS settings and routes. Setting it bypasses the per-profile state location. The embedded client sets it from `embed.Options.StatePath`. |
| `OPENZRO_FLOW_LOGGER_MAX_EVENTS` | All | Maximum number of traffic events the client buffers while it cannot deliver them to management (default: `50000`, about 10 MB). The oldest events are dropped beyond that. |

## Updates

| Variable | Platform | Description |
|---|---|---|
| `OPENZRO_UPDATE_MANIFEST_TEMPLATE` | Desktop | URL template of the per-version update manifest used when management directs a client to a version. It must contain `{version}`. Defaults to the manifest attached to each GitHub release; point it at a mirror if clients cannot reach GitHub. Set it to an empty value to disable this update path. |
| `OPENZRO_UPDATE_MANIFEST_URL` | Desktop | URL of the static update manifest the daemon uses as a fallback to install critical updates on clients that management does not direct. Set it to an empty value to disable the fallback. |

## Debugging

| Variable | Platform | Description |
|---|---|---|
| `OZ_PPROF_ADDR` | All | Start a Go pprof HTTP endpoint at this address (e.g. `localhost:6060`) for profiling CPU, memory and goroutine usage. |
| `OZ_LISTEN_DEBUG_EVENT` | Windows | When set, the daemon listens on the `Global\OpenzroDebugTriggerEvent` Windows event and creates a debug bundle whenever the event is signaled. |

## Docker entrypoint

The `openzro/openzro` container image reads two more variables in its entrypoint script:

| Variable | Description |
|---|---|
| `OZ_ENTRYPOINT_SERVICE_TIMEOUT` | Seconds to wait for the daemon to log that it started before continuing with a warning (default: `5`). |
| `OZ_ENTRYPOINT_LOGIN_TIMEOUT` | Seconds to wait for the log to show that the peer is already registered (default: `1`). If it does not, the entrypoint runs `openzro up`. |

<Note>
Variables with the legacy `WT_` prefix are only read for options that mirror CLI flags. The variables on this page
must use the prefix shown.
</Note>
