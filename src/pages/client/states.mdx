# Client States and Status Icons

The openZro desktop client surfaces what it's doing through a single systray
icon that changes shape and badge depending on the connection state. The
icon family is consistent across Linux (GNOME / KDE / others), macOS
(menu bar) and Windows (notification area) — same shield silhouette,
same badge anchor at the bottom-right corner.

This page documents every icon you can see, what triggers it, and what
to do about it. Hovering over the icon shows a tooltip such as
`Openzro (Connected)`, and the first menu item repeats the state.

## State transitions

Typical happy-path lifecycle when a user runs `openzro up`:

```
Disconnected  ──▶  Connecting  ──▶  Connected
                       │
                       └──▶  Disconnected  (login or connection failure)
```

Background events that can shift state without user action:

- **Session expiry** (when the administrator enabled login expiration) →
  `Disconnected`, and the client opens the login page so you can log in again.
- **Network change** (WiFi roaming, sleep/wake) → `Connected` →
  `Connecting` → `Connected`.
- **Management restart** (operator-side, e.g. a Helm upgrade) →
  `Connected` → `Connecting` → `Connected` once the control channel
  reconnects.
- **Update announced by management** → adds the update badge without
  changing the connected/disconnected state.

## Updates

The client does not check for updates on its own: the management server tells
it when a newer version is available. What happens next depends on the
platform:

- **macOS**: the **About** menu shows **Install openZro X**, which downloads,
  verifies and installs the update. When the administrator forces the
  update, the client installs it without asking.
- **Windows**: the **About** menu shows **Download openZro X (.msi)**, which
  opens the installer for the new version in your browser.
- **Linux**: the icon shows the update badge; upgrade with your package
  manager.

## Login success page

When you run `openzro login` (or trigger SSO via the GUI), the desktop
client opens your default browser to complete the OAuth/PKCE handshake.
After a successful sign-in you'll see a confirmation page served by the
client itself on `localhost`:

> **You're in the mesh.**
> Device registered, posture verified, keys exchanged. Your peer is
> now routable across the openZro network.

The page tries to close itself automatically after 10 seconds. Modern
browsers restrict `window.close()` to scripts that opened the window —
since the openZro client launches the browser via the OS shell, the
close call is sometimes blocked. When that happens the countdown is
replaced by a "You can safely close this window." note, and you can
close the tab manually. Either way, the desktop client has already
completed the handshake by the time the page renders.

## Troubleshooting state-stuck scenarios

If the icon stays in a state longer than expected, the
[Troubleshooting](/help/troubleshooting-client) page covers the common
causes. Quick reference:

- **Stuck on Connecting (over 30 s)**: management URL unreachable, or DNS
  is broken inside the daemon's network namespace. `openzro status`
  prints the management URL it's trying.
- **Error icon after clicking Connect**: the daemon is not running.
  Start the service and try again.
- **Connected but no peer traffic**: check that a policy allows the
  traffic and that the peer passes the policy's posture checks. In
  `openzro status --detail`, look at whether the remote peer is listed
  and connected.
- **Update badge stays after a package upgrade**: restart the daemon so
  it reports its new version to the management server.
